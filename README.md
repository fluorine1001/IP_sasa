# 작은 로켓의 큰 모험 · IP_sasa

시간선에 비행 조작을 설계하고 실제 발사의 관측·다시보기를 비교해 푸는 2D 로켓 퍼즐입니다. 물리 지식을 미리 요구하지 않고 실패에서 원인을 좁혀가는 게임을 지향합니다. 미래 궤도, 무료 예행 비행, 정답 계획은 플레이 화면에 제공하지 않습니다.

## 새 개발자: 실행부터

GitHub Desktop으로 [IP_sasa](https://github.com/fluorine1001/IP_sasa)를 자신의 폴더에 clone합니다. 현재 팀 기준 브랜치 `codex/game-workshop`에서 개인 브랜치를 만듭니다. Windows에서는 Node.js 24 이상을 한 번 설치한 뒤 다음 파일을 더블클릭합니다.

- **`play.cmd`**: 처음에는 의존성을 자동 설치하고 게임을 빌드해 엽니다. 이후에는 변경이 있을 때만 다시 빌드합니다. 플레이 중에는 로컬 서버나 명령 창을 유지할 필요가 없습니다.
- **`editor.cmd`**: 개발 서버와 제작 에디터를 자동으로 엽니다. 다른 프로그램이 5173을 쓰면 다음 빈 포트를 선택합니다. 파일 저장을 위해 명령 창을 유지하고, 끝낼 때 Ctrl+C로 종료합니다.
- **`dist/play.html`**: 생성 후에는 이 파일 하나를 브라우저로 열면 됩니다. Node.js·인터넷·서버 없이 복사해서 플레이할 수 있습니다. CI의 `playable-build` 결과물에도 포함됩니다. 생성물은 Git에 올리지 않습니다.

첫 실행과 의존성 업데이트에는 `npm ci`를 위한 인터넷 연결이 필요합니다. GitHub Desktop에서 Pull한 뒤 `play.cmd`를 열면 소스·스테이지·빌드 설정 변경을 감지합니다. `dist/play.html`만 직접 열면 자동 갱신하지 않으므로 업데이트 후에는 실행기를 사용하세요. 설정·완료 기록은 브라우저 저장소에 있으며 localhost판과 파일판 사이에 자동 이동하지 않습니다. 파일판 저장소 동작은 브라우저에 따라 다를 수 있습니다.

터미널을 사용하는 개발자는 기존 방식도 사용할 수 있습니다.

```sh
npm ci
npm run dev
```

게임: http://127.0.0.1:5173/

독립 에디터: http://127.0.0.1:5173/editor.html

`editor.cmd`는 로컬 제작소를 엽니다. 팀 공유는 `npm run workshop` 또는 편집 키를 설정한 `npm run workshop:lan`으로 독립 게임·제작소·저장 API 서버를 실행합니다. [공유 서버 안내](docs/shared-workshop.md), [무료 인터넷 호스팅·이전 안내](docs/free-hosting.md)를 참고하세요. 일반 `dist/` 게임 배포에는 제작 도구·검증 계획이 없습니다. 현재 데스크톱 브라우저 게임이며 Steam용 네이티브 패키징은 별도 작업입니다.

```sh
npm run check              # TypeScript
npm run check:boundaries   # 담당 모듈 경계·UUID
npm test                   # 단위 검사
npm run audit:stages       # 기준 풀이·우연 성공 표본
npm run format
npm run verify            # 위 검사·빌드·포맷 검사
npx playwright install chromium
npm run test:e2e           # 실제 Chromium 조작
npm run build
npm run build:offline     # 서버 없는 dist/play.html만 생성
npm run preview
```

Playwright는 개발 서버를 자동 실행하거나 실행 중인 서버를 재사용합니다. 첫 실행은 브라우저 설치가 필요합니다. 검사 결과와 화면 캡처는 Git에서 제외한 test-results/에 저장합니다.

Windows에서 테스트용 서버 종료가 멈추면 별도 터미널의 개발 서버를 재사용할 수 있습니다. 예: `npm run dev -- --port 5190 --strictPort`를 켜고 PowerShell에서 `$env:E2E_PORT='5190'; npm run test:e2e`를 실행합니다. 포트 설정은 테스트 프로세스에만 적용됩니다.

```text
data/stages/<UUID>.json       스테이지 담당: 에디터 저장, 파일마다 독립
src/

  main.ts                    화면 연결·프레임 루프
  style.css                  공용 버튼·패널·메뉴 스타일
  screens/
    flight/                  게임 시스템: 관제석·계획·진행 바

      timeline.ts            진행 바와 세부 계획 목록
      planner.ts             드래그·배치·선택 조작 편집
      propulsion.ts          기체 성능 안내
      controls.ts            자체 SVG 아이콘
      base.css, console.css, planning.css

  editor/                    개발용 장면·목표 제작·저장·설계 검사
  world/                     상태·추진·충돌·목표·관측·재생
  physics/                   DOM 없는 벡터·궤도 계산
  render/                    캔버스·카메라·로켓 아트
  stages/                    UUID 생성·스키마 검사·파일 자동 발견
public/assets/               재사용 이미지·자산 설명
scripts/                     검사·캡처·이미지 출력

```

튜토리얼·설정은 자신의 폴더에서 코드와 CSS를 함께 수정합니다. 화면은 App을 받아 Screen을 반환하고 dispose()에서 이벤트를 정리합니다. 기존 메뉴 연결이 되어 있어 내용 변경에 main.ts를 건드릴 필요가 없습니다. 물리 모듈이나 다른 화면 CSS를 직접 가져오지 않습니다.

스테이지는 JSON을 자동 발견하므로 공용 목록 파일을 수정하지 않습니다. 상세 경계·Git 작업 순서는 [CONTRIBUTING](CONTRIBUTING.md), [작업 보드](docs/team-board.md), AI 지침은 [AGENTS](AGENTS.md)에 있습니다.

## 플레이

‘탐사 시작’에서 스테이지를 선택합니다. 도움말과 설정은 독립 화면입니다.

처음에는 메인 메뉴의 **튜토리얼 스테이지 → 첫 비행 실험실**을 권장합니다. 하나의 행성과 두 단 로켓으로 목표 확인, 예약 편집, 분리·재점화·회전·관성 비행, 실제 기록 재생, 한 변수 변경과 두 결과 비교까지 경험합니다. 반투명 검정 화면의 투명한 원이 현재 조작을 강조하고 짧은 행동 안내를 표시합니다. 실습은 7개 활동 묶음이며 완료 후 ‘다음’을 직접 누릅니다. 이전·목록으로 다시 볼 수 있고, 강조가 사라져도 설명은 남습니다. 패널은 드래그·최소화할 수 있고 세부 설명은 내부 스크롤로 읽습니다. 본편에는 풀이 절차·상황별 조언·실습 안내가 나타나지 않고, 도움말은 간단한 조작 참고로 남습니다.

훈련 완료에는 실제 비행 목표와 실습 행동이 모두 필요합니다. 목표를 먼저 달성했다면 남은 재생·비교 실습을 마쳐 완료할 수 있습니다. 훈련 완료 기록은 본편과 별도이며 예전 분할 튜토리얼 기록으로 새 훈련이 완료되지 않습니다.

- 시간 바를 **클릭하거나 손잡이를 드래그**해 예약 시각을 고른 뒤 **출력 / 끄기 / 회전 / 분리** 버튼을 누릅니다. ‘예약 시각’ 숫자는 0.01초 단위로 직접 입력할 수 있습니다. 바에 초점을 두고 방향키로 0.01초씩, Home/End로 양 끝에 이동합니다. 이는 시각 선택일 뿐 예행 비행이 아닙니다.
- 조작 그림을 시간선으로 직접 끌어 놓는 방식도 가능합니다. 배치된 예약 그림을 끌면 그 예약의 실행 시각이 바뀝니다. 시간 바를 이동하는 것만으로 기존 예약은 바뀌지 않습니다.
- 출력·회전·수정 추진은 클릭해 값을 조절합니다. 방향은 발사대 기준 −180°~180°이며 기체 성능에 따라 회전에 시간이 걸립니다. 분리·끄기는 슬라이더 없이 선택·이동·삭제합니다.
- 출력 편집에는 불꽃 크기·힘 화살표·연료 흐름을 비교하는 기체 그림이 있습니다. 방향은 방향판으로 고르며 본체와 분리체는 구성 그림으로 구분합니다. 첫 출력 안내는 추진 가속 눈금과 연료 지속 시간도 제공합니다. 이륙 가능 여부·필요 출력·성공 가능성·목표까지 경로를 예측하지 않습니다.
- ‘목표 조건 확인’에서 범위·유지 시간·달성 순서·지도 위치를 확인합니다. 비행 기록에는 관측 수치와 측정 시각, 두 발사의 결과 및 같은 시각의 실제 위치·속력·연료를 표시합니다. 기록이 끝난 구간은 ‘상태 없음’으로 표시합니다.
- 발사하면 계획은 확정됩니다. 일시정지 중에도 예약을 추가/수정하지 않습니다. 진행 바에서 현재 시각과 실제 실행 여부를 확인합니다.
- 분리하면 몸체가 짧아지고 부스터가 따로 움직입니다. 그림과 충돌은 같은 치수를 사용합니다. 다음 엔진은 자동 점화하지 않습니다.
- 관제석의 **기록**에서 경로 그림을 선택하면 현재 지도에 실제 경로만 점선으로 표시합니다. 같은 카드의 **재생**으로 영상을 시작합니다. 비행 종료 직후에는 현재 기록의 마지막 시각에서 자동 다시보기가 열려 즉시 시간을 탐색할 수 있습니다. **계획으로 돌아가기**로 재생을 종료하면 바로 편집할 수 있습니다. 진행 중인 비행으로 돌아갈 때는 **현재 비행으로**입니다. 별도의 계획 편집 모드 전환·종료 질문은 없습니다. 과거 기록은 현재 계획 변경에 영향받지 않습니다.
- Space: 정지/재개, WASD·왼쪽/가운데 드래그: 카메라 이동, 휠: 확대, C: 추적 복귀. 패널 조작은 카메라를 움직이지 않습니다. 배속은 선택창에서 0.25·0.5·1·2·4·8배로 고르며 모든 임무·튜토리얼·재생에서 유지됩니다. 1배는 실제 1초에 게임 2초입니다. 재생에는 움직이는 노이즈·회색 주사 띠가 있습니다.
- 빨간 ×로 임무를 직접 나갑니다. 스테이지 간 관측·연료·분리체·기회는 독립적입니다. 같은 스테이지의 환경은 고정하고 시도를 누적합니다. 중력/속력 부표 예약은 제거되었습니다.

## 에디터로 제작

1. **새 스테이지**로 새 UUID를 발급합니다. 기존 파일은 해당 담당자와 조율한 뒤 수정합니다.
2. 지도에 천체·정거장·게이트·위험 영역·경로 등을 배치합니다. 다중 선택·복제·묶음 복사·undo/redo가 가능합니다.
3. **스테이지 규칙**에서 출발 천체·지면 각도·로켓·시간·예약 횟수·발사 기회를 정합니다. 표면 발사점은 자동 계산합니다.
4. **결과 중심 목표 만들기**에서 기체·대상·허용 영역·유지 시간을 지정합니다. 원형 궤도·일반 궤도·랑데부·회수·탈출·환경 유지가 같은 Condition/Expression 블록으로 생성됩니다. 고급 블록으로 자유롭게 확장할 수 있습니다. 임무 이름을 엔진에 등록하지 않습니다. [목표 제작](docs/goal-system.md)을 참고합니다.
5. 실패를 구별할 관측·단서를 설계합니다. F5로 직접 계획하고 여러 발사를 비교합니다. 제작 시험의 성공 기록을 기준 경로로 저장합니다.
6. **전체 조작 구성 탐색**으로 모든 허용 조작의 순서·횟수·대상을 생성해 유효해를 조사하고 연결 표본을 그룹으로 봅니다. 의도한 해를 따로 분류·보호하지 않습니다. **이어서 더 조사**는 이전 조사 상태를 재사용합니다. 차단안은 다른 발견 해가 얼마나 함께 사라지는지도 검사합니다. 유한 검사로 모든 연속 해를 찾았다는 증명은 아닙니다. [탐색 범위와 알고리즘](docs/editor-search.md)을 참고하세요.
7. **초안 저장**은 연결한 서버의 data/stages/<UUID>.json에 published:false로 저장합니다. **검사 후 게임에 추가**는 서버 재검사 후 공개합니다. 보관함에서 최신 목록·열기·삭제를 관리하고 오래된 수정본의 덮어쓰기는 거절합니다. 다른 clone은 공유 서버 주소를 설정해 최신 공개 스테이지를 읽거나 기존 Git/PR 방식으로 JSON을 공유할 수 있습니다.

### 시간과 예약 횟수

| 규칙                      | 효과                                                                    |
| ------------------------- | ----------------------------------------------------------------------- |
| 타임라인 길이             | 조작 예약의 마지막 시각. 빈칸이면 전체 임무 시간                        |
| 타임라인 예약 시간 무제한 | 시간선을 늘리거나 늦은 시각을 입력해 예약. 유한한 임무 종료 이후는 제외 |
| 전체 임무 제한 시간       | 관성 비행·관측을 포함하는 종료 시각                                     |
| 전체 임무 시간 무제한     | 시간 초과로 종료하지 않음. 목표 달성·충돌·범위 이탈·직접 중단은 적용    |
| 목표 종료 시각 무제한     | 해당 목표를 후반에도 판정. 목표별 시간 창은 임무 제한과 독립적          |
| 자동 검사 시간            | 무제한 임무도 유한한 시간까지만 검사. 빈칸이면 초기 임무 표시 길이      |
| 종류별 예약 횟수          | 출력·끄기·회전·분리·수정 추진 각각 지정. 0은 금지, 빈칸은 무제한        |

무제한일 때 숫자는 시간선의 초기 표시 길이입니다. **시간선 늘리기** 또는 세부 목록의 시각 입력으로 확장합니다. 발사·재생은 기록 시간에 맞춰 표시 범위를 늘립니다. JSON에는 Infinity 대신 maxTimeUnlimited / timelineUnlimited 플래그를 저장합니다.

첫 발사는 추가 예약 횟수에 포함하지 않습니다. 기존 명령 하나에 출력과 방향이 함께 있으면 각각의 한도를 소비합니다. UI와 엔진이 동일하게 한도를 검사합니다. 자동 검사 시간에 성공하지 못한 무제한 비행은 ‘검사 범위 내 성공 없음’이며 실제 게임의 실패 판정이 아닙니다.

## 이미지·상태·계약

로켓 아트 원본은 src/render/rocket-sprite.ts, 세계 치수는 src/world/hull.ts입니다. public/assets/rockets/의 투명 PNG 7개와 manifest는 같은 렌더러로 출력합니다. [자산 안내](public/assets/README.md)를 읽고 개발 서버를 켠 뒤 `node scripts/export-rocket-assets.mjs`로 재생성합니다.

설정과 완료 ID는 브라우저에, 비행 기록은 스테이지 세션에 저장합니다. 제작 초안도 브라우저에 임시 저장하지만 공유본은 저장된 서버 JSON 또는 Git입니다. 플레이 로그를 서버에 전송하지 않습니다. 행성 물리량의 시도별 랜덤화는 실행하지 않으며 같은 환경을 유지합니다. 구버전 변형·부표 데이터는 읽기 호환용으로만 남고 플레이에서 실행되지 않습니다.

축척된 2D 뉴턴 역학입니다. 대기·가열·손상은 게임용 근사이고 블랙홀은 뉴턴 중력 우물/흡수 경계입니다. 초심자 난이도와 재미는 실제 플레이로 확인해야 합니다.
