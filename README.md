# 작은 로켓의 큰 모험 · IP_sasa

시간선에 비행 조작을 설계하고 실제 발사의 관측·다시보기를 비교해 푸는 2D 로켓 퍼즐입니다. 물리 지식을 미리 요구하지 않고 실패에서 원인을 좁혀가는 게임을 지향합니다. 미래 궤도, 무료 예행 비행, 정답 계획은 플레이 화면에 제공하지 않습니다.

## 새 개발자: 실행부터

GitHub Desktop으로 [IP_sasa](https://github.com/fluorine1001/IP_sasa)를 자신의 폴더에 clone합니다. 현재 팀 기준 브랜치 `codex/game-workshop`에서 개인 브랜치를 만듭니다. Node.js 24 이상을 설치하고 저장소 폴더에서 실행합니다.

```sh
npm ci
npm run dev
```

게임: http://127.0.0.1:5173/

개발 에디터: http://127.0.0.1:5173/?editor=1

제작 코드와 파일 저장 API는 개발 서버에만 있습니다. 서버는 localhost 전용이며 이미 5173을 사용 중이면 기존 서버를 종료하고 다시 실행합니다. `dist/` 배포 결과에는 제작 기준 계획을 포함하지 않습니다. 현재 데스크톱 브라우저 게임이며 Steam용 네이티브 패키징은 별도 작업입니다.

```sh
npm run check              # TypeScript
npm run check:boundaries   # 담당 모듈 경계·UUID
npm test                   # 단위 검사
npm run audit:stages       # 기준 풀이·우연 성공 표본
npm run format
npm run verify            # 위 검사·빌드·포맷 검사
npx playwright install chromium
npm run test:e2e           # 실제 Chromium 조작
npm run build
npm run preview
```

Playwright는 개발 서버를 자동 실행하거나 실행 중인 서버를 재사용합니다. 첫 실행은 브라우저 설치가 필요합니다. 검사 결과와 화면 캡처는 Git에서 제외한 test-results/에 저장합니다.

## 폴더와 네 명의 작업 경계

```text
data/stages/<UUID>.json       스테이지 담당: 에디터 저장, 파일마다 독립
src/
  app/core.ts                공용 App / Screen / Settings
  main.ts                    화면 연결·프레임 루프
  style.css                  공용 버튼·패널·메뉴 스타일
  screens/
    flight/                  게임 시스템: 관제석·계획·진행 바
      screen.ts              플레이 세션과 상태
      timeline.ts            진행 바와 세부 계획 목록
      planner.ts             드래그·배치·선택 조작 편집
      propulsion.ts          기체 성능 안내
      controls.ts            자체 SVG 아이콘
      base.css, console.css, planning.css
    tutorial/                튜토리얼 담당: screen.ts + style.css
    settings/                설정 담당: screen.ts + style.css
    title.ts, stages.ts      기지와 스테이지 선택
  editor/                    개발용 장면·목표 제작·저장·설계 검사
  world/                     상태·추진·충돌·목표·관측·재생
  physics/                   DOM 없는 벡터·궤도 계산
  render/                    캔버스·카메라·로켓 아트
  stages/                    UUID 생성·스키마 검사·파일 자동 발견
public/assets/               재사용 이미지·자산 설명
scripts/                     검사·캡처·이미지 출력
tests/                       단위 검사, e2e/ 브라우저 검사
docs/                        계약·검증 기록
.github/                     작업/PR 양식·CI
```

튜토리얼·설정은 자신의 폴더에서 코드와 CSS를 함께 수정합니다. 화면은 App을 받아 Screen을 반환하고 dispose()에서 이벤트를 정리합니다. 기존 메뉴 연결이 되어 있어 내용 변경에 main.ts를 건드릴 필요가 없습니다. 물리 모듈이나 다른 화면 CSS를 직접 가져오지 않습니다.

스테이지는 JSON을 자동 발견하므로 공용 목록 파일을 수정하지 않습니다. 상세 경계·Git 작업 순서는 [CONTRIBUTING](CONTRIBUTING.md), [작업 보드](docs/team-board.md), AI 지침은 [AGENTS](AGENTS.md)에 있습니다.

## 플레이

‘탐사 시작’에서 스테이지를 선택합니다. 도움말과 설정은 독립 화면입니다.

- 시간선 아래 **출력 / 끄기 / 회전 / 분리** 그림을 원하는 시각으로 끌어 놓습니다. 도구 클릭 후 시간선 클릭으로도 배치합니다. 배치된 그림을 끌면 실행 시각이 바뀝니다.
- 출력·회전·수정 추진은 클릭해 값을 조절합니다. 방향은 발사대 기준 −180°~180°이며 기체 성능에 따라 회전에 시간이 걸립니다. 분리·끄기는 슬라이더 없이 선택·이동·삭제합니다.
- 첫 출력 안내는 추진 가속 눈금과 연료 지속 시간입니다. 이륙 가능 여부·필요 출력·성공 가능성·목표까지 경로를 예측하지 않습니다.
- 발사하면 계획은 확정됩니다. 일시정지 중에도 예약을 추가/수정하지 않습니다. 진행 바에서 현재 시각과 실제 실행 여부를 확인합니다.
- 분리하면 몸체가 짧아지고 부스터가 따로 움직입니다. 그림과 충돌은 같은 치수를 사용합니다. 다음 엔진은 자동 점화하지 않습니다.
- 기록 카드의 ▶ 또는 최근 다시보기로 당시 예약과 실제 실행을 확인합니다. 현재 계획을 바꾸어도 과거 기록은 바뀌지 않습니다.
- Space: 정지/재개, WASD·가운데 드래그: 카메라 이동, 휠: 확대, C: 추적 복귀. 다시보기는 반투명 로켓과 약한 노이즈로 구별합니다.
- 빨간 ×로 임무를 직접 나갑니다. 스테이지 간 관측·연료·분리체·기회는 독립적입니다. 같은 스테이지의 환경은 고정하고 시도를 누적합니다. 중력/속력 부표 예약은 제거되었습니다.

## 에디터로 제작

1. **새 스테이지**로 새 UUID를 발급합니다. 기존 파일은 해당 담당자와 조율한 뒤 수정합니다.
2. 지도에 천체·정거장·게이트·위험 영역·경로 등을 배치합니다. 다중 선택·복제·묶음 복사·undo/redo가 가능합니다.
3. **스테이지 규칙**에서 출발 천체·지면 각도·로켓·시간·예약 횟수·발사 기회를 정합니다. 표면 발사점은 자동 계산합니다.
4. 목표 블록에서 비행체·기준 대상·물리량·수식·구간 통계·유지·순서를 조합합니다. 임무 이름을 엔진 코드에 등록하지 않습니다. [목표 제작](docs/goal-system.md)을 참고합니다.
5. 실패를 구별할 관측·단서를 설계합니다. F5로 직접 계획하고 여러 발사를 비교합니다. 제작 시험의 성공 기록을 기준 경로로 저장합니다.
6. 기준 성공·반례·조작 여유 검사를 확인합니다. 자동 표본 검사는 재미나 우연 성공 불가능의 증명이 아닙니다.
7. **초안 저장**은 data/stages/<UUID>.json에 published:false로 저장합니다. 브라우저 임시 저장만으로 Git 파일이 생기지는 않습니다. **검사 후 게임에 추가**는 검사 조건을 통과한 JSON을 공개합니다. 팀 공유는 PR 리뷰·병합으로 진행합니다.

### 시간과 예약 횟수

| 규칙                      | 효과                                                                    |
| ------------------------- | ----------------------------------------------------------------------- |
| 타임라인 길이             | 조작 예약의 마지막 시각. 빈칸이면 전체 임무 시간                        |
| 타임라인 예약 시간 무제한 | 시간선을 늘리거나 늦은 시각을 입력해 예약. 유한한 임무 종료 이후는 제외 |
| 전체 임무 제한 시간       | 관성 비행·관측을 포함하는 종료 시각                                     |
| 전체 임무 시간 무제한     | 시간 초과로 종료하지 않음. 목표 달성·충돌·범위 이탈·직접 중단은 적용    |
| 목표 종료 시각 무제한     | 해당 목표를 후반에도 판정. 목표별 시간 창은 임무 제한과 독립적          |
| 자동 검사 시간            | 무제한 임무도 유한한 시간까지만 검사. 빈칸이면 초기 임무 표시 길이      |
| 종류별 예약 횟수          | 출력·끄기·회전·분리·수정 추진 각각 지정. 0은 금지, 빈칸은 무제한        |

무제한일 때 숫자는 시간선의 초기 표시 길이입니다. **시간선 늘리기** 또는 세부 목록의 시각 입력으로 확장합니다. 발사·재생은 기록 시간에 맞춰 표시 범위를 늘립니다. JSON에는 Infinity 대신 maxTimeUnlimited / timelineUnlimited 플래그를 저장합니다.

첫 발사는 추가 예약 횟수에 포함하지 않습니다. 기존 명령 하나에 출력과 방향이 함께 있으면 각각의 한도를 소비합니다. UI와 엔진이 동일하게 한도를 검사합니다. 자동 검사 시간에 성공하지 못한 무제한 비행은 ‘검사 범위 내 성공 없음’이며 실제 게임의 실패 판정이 아닙니다.

## 이미지·상태·계약

로켓 아트 원본은 src/render/rocket-sprite.ts, 세계 치수는 src/world/hull.ts입니다. public/assets/rockets/의 투명 PNG 7개와 manifest는 같은 렌더러로 출력합니다. [자산 안내](public/assets/README.md)를 읽고 개발 서버를 켠 뒤 `node scripts/export-rocket-assets.mjs`로 재생성합니다.

설정과 완료 ID는 브라우저에, 비행 기록은 스테이지 세션에 저장합니다. 제작 초안도 브라우저에 임시 저장하지만 팀 공유본은 저장된 JSON과 Git입니다. 플레이 로그를 서버에 전송하지 않습니다. 구버전 부표 데이터 필드는 읽기 호환용으로 남으며 실행되지 않습니다.

축척된 2D 뉴턴 역학입니다. 대기·가열·손상은 게임용 근사이고 블랙홀은 뉴턴 중력 우물/흡수 경계입니다. 초심자 난이도와 재미는 실제 플레이로 확인해야 합니다.
