# 유효해 집합 탐색 계약

제작자가 정한 환경·장치 제약·성공 조건만 판정 기준입니다. ‘의도한 해’를 별도 종류로 찾거나 보호하지 않습니다. referencePlans는 실제 성공을 재검사하는 제작용 기록이고, 전역 탐색에서는 다른 표본과 같은 초기 입력입니다. 플레이 배포에는 포함하지 않습니다.

## 조사 범위

- 기본은 **전체 조작 구성 탐색**입니다. 허용된 출력·끄기·회전·분리 또는 수정 추진의 순서와 반복 횟수를 생성합니다. 분리 뒤에는 해당 분리체의 엔진·회전 명령도 포함합니다. 첫 출력은 0부터 최대 출력, 방향은 전체 방향 범위입니다. 모든 변수는 기본적으로 조사합니다.
- 종류별 한도가 모두 유한하면 그 합까지 조사합니다. 무제한 예약은 기본 6개까지이며 제작자가 범위를 바꿀 수 있습니다. 현재 한 번의 조사 범위는 최대 256개 예약입니다. 더 긴 구성이나 자동 검사 종료 이후의 비행을 조사했다고 표시하지 않습니다.
- 특정 구성을 고르면 그 구성의 변수 범위를 좁히거나 고정할 수 있습니다. 이는 전체 탐색과 다른 **범위 조사**로 명확히 표시합니다.
- 시간 변수는 이전 명령 이후 남은 시간 구간에 대응시킵니다. 조작 순서를 유지하면서 모든 비감소 시각 배열과 같은 시각의 명령을 표현합니다. 복합 출력·회전 명령은 같은 시각의 개별 명령으로도 표현할 수 있습니다. 한도를 넘는 계획은 성공 표본에 포함하지 않습니다.

## 알고리즘과 비용

`solution-space.ts`는 가능한 다음 명령 상태에 대한 접미 프로그램 개수를 동적 계획법으로 세고 순번을 실제 프로그램으로 바꿉니다. 전체 목록을 메모리에 만들지 않습니다. 서로소 간격으로 순번을 순회하고 예약 길이를 번갈아 조사해 초반부터 서로 다른 순서·대상과 긴 프로그램에 접근합니다. 개수 집계 상태가 10만 개를 넘으면 개수를 ‘집계 한도 초과’로 표시하고 지연 열거를 계속합니다.

`global-search.ts`는 새 구성 조사와 기존 구성의 연속 값 세분화에 교대로 기회를 줍니다. 각 구성에서는 정규화된 큰 미조사 셀을 우선하는 전역 분할 75%, 실제 목표 진행값을 활용하는 세분화 25%를 사용합니다. 특정 검증 기록 주변을 우선 보호하지 않습니다. 실패 표본 하나로 구간 전체를 제거하지 않습니다.

판정은 본 게임과 같은 엔진과 0.01초 물리 간격을 사용합니다. 검색을 빠르게 보이게 하려고 물리 간격을 키우지 않습니다. 검색 중에는 전체 영상 프레임을 저장하지 않고, 대표 경로 요청 때만 다시 실제 비행을 기록합니다. 하나의 공유 검사 예산을 넘지 않으며 작업자는 별도 스레드에서 실행됩니다. 편집 변경은 이전 작업을 종료하고 새 revision으로 시작합니다. UI 갱신은 최대 초당 10회입니다.

**이어서 더 조사**는 기존 캐시·집합·열거 위치·미조사 셀을 유지한 채 검사 예산을 추가합니다. 한 revision에서 최대 8192회까지 누적할 수 있습니다. **중지**는 현재 결과를 남기고 계산을 끝냅니다. 조건이나 환경 변경은 판정 대상 자체가 달라졌으므로 이전 결과를 폐기하고 다시 조사합니다.

## 그룹과 차단 수정안

같은 조작 순서·대상의 성공 표본을 연결할 때 ¼·½·¾ 지점도 실제로 비행해 성공을 확인합니다. 각 그룹의 대표 비행, 확인한 실제 시각·출력·방향 범위, 성공 표본 수·확인한 연결 수·성공 표본 사이 최대 간격을 보여 줍니다. 간격 막대는 넓이가 클수록 성긴 표본임을 뜻하며 성공 확률 막대가 아닙니다. 24개 단위 페이지로 모든 발견 그룹을 열람할 수 있습니다.

성공 후 실행되지 않은 예약은 제거한 계획을 다시 실제 비행해 성공한 경우에만 제거합니다. 이 재판정도 공통 검사 예산을 소비합니다. 다른 예약 구성의 그룹이 정확히 같은 실현 계획을 공유하면 중복을 합칩니다. 물리값을 반올림해 같다고 간주하거나 범위가 겹친다는 이유로 다른 그룹을 합치지는 않습니다. 예산이 부족해 접두 계획을 재판정하지 못한 표본에는 중복이 남을 수 있습니다.

이 그룹은 연속 공간의 연결성을 증명한 집합이 아닙니다. 중간점까지 성공해도 그 사이에 실패하는 좁은 구간이 있을 수 있고, 조사하지 않은 연결 통로 때문에 실제 하나의 집합이 여러 그룹으로 보일 수 있습니다. 범위의 직사각형 안 모든 조합이 성공한다는 뜻도 아닙니다.

차단안은 유지 시간 증가·기존 물리량 경계 축소라는 유한한 후보군을 실제 엔진으로 재검사합니다. 선택한 그룹의 저장된 표본을 모두 막은 수정안만 제시하고, 다른 발견 그룹·검증 기록과 그 근처 표본 중 몇 개가 남는지 표시합니다. 특정 해의 보존을 필수로 강제하지 않습니다. 가능한 모든 스테이지 수정 방법이나 그룹의 모든 미검사 해까지 차단했다는 증명은 아닙니다.

## 제작 흐름

결과 목표 생성 → 지도 배치·자원 설정 → 전체 탐색 → 그룹의 실제 경로 확인 → 허용하고 싶지 않은 물리 결과가 있으면 성공 조건 수정 → 재탐색입니다. 정답 계획을 고정하고 그 주변만 찾는 도구가 아닙니다. 원형 궤도 목표는 이심률·거리 띠·엔진 꺼짐을 한 바퀴 내내 만족해야 하며, 환경 유지 목표는 연속 유지 또는 실제 시간 구간의 유지 비율로 생성합니다. 고급 조건 블록으로 자유롭게 조합할 수 있습니다.

유한한 검사로 모든 연속 해를 발견했다고 보장할 수는 없습니다. 검사 예산·조사한 구성 수·최대 예약 개수·검사 시간·미조사 구성 여부를 보고 탐색 범위를 판단해야 합니다. 자동 검사는 재미와 초심자 이해의 증명이 아닙니다.

## 비용 측정

`node scripts/benchmark-search.mjs`는 8·13·20변수 × 2·16·64개 고정 천체에서 64회씩 실제 비행을 조사합니다. 2026-10-14 로컬 측정은 66~876ms, 73~975회/초, 관측 시점의 Node heap 23~35MiB였습니다. 검사 비행이 0.6초로 짧고 초기 컴파일·GC·다른 실행의 영향을 받으므로 일반 임무의 처리량으로 환산하지 않습니다. 물리 간격은 모두 0.01초이며 64개 상호 중력 천체의 장시간 검사·작업자 메모리·취소 지연에는 별도 스트레스 측정이 필요합니다.
