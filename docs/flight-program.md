# 발사 계획과 기록 재생

## 플레이 계약

계획 → 실제 발사 → 관측 → 다시보기 → 다음 계획 수정의 루프입니다. 플레이 화면은 계획, 확정된 비행, 기록 재생을 별도 상태로 관리합니다. 비행 중에는 엔진 조작, 단 분리, 수정 추진, 부표 방출을 추가하거나 바꿀 수 없습니다. 키보드와 지도 클릭도 이 잠금을 지킵니다. 일시정지해도 계획은 잠겨 있습니다.

발사 전에 첫 출력·방향을 정하고 시간별 엔진 출력, 끄기, 방향 전환, 단 분리, 장비 방출을 예약합니다. 같은 시각의 엔진 명령은 작성 순서대로 실행됩니다. 먼저 단을 분리한 뒤 다음 엔진을 점화하는 순서를 지켜야 합니다. 분리체를 대상으로 엔진 명령도 예약할 수 있으므로 회수 미션을 같은 체계로 작성합니다.

타임라인 픽토그램을 끌어 시각을 바꾸거나 입력 필드로 지정합니다. 같은 시각 순서 변경과 삭제도 가능합니다. 미래 경로를 계산하지 않습니다. 발사 전 출력계는 현재 장치의 추력/무게 비, 단별 최대 분사 시간과 점화 횟수를 보여줍니다. 연료 경고는 장치의 소모량만 계산하며 성공 궤도를 예측하지 않습니다. 수치는 게임 축척 단위입니다.

진행 바는 임무 시간 제한을 전체 길이로 삼습니다. 현재 시각이 이동하고 명령의 픽토그램은 실행될 때 밝아집니다. 첫 대기권 미션은 18초로 구성하여 몇 초 간격의 분리·제동을 읽기 쉽게 했습니다.

## 과거 발사와 다음 계획의 격리

Run.initialPlan은 발사 순간의 계획 복사본입니다. 기록 카드에는 다음 항목을 별도로 둡니다.

- scheduledPlan: 발사 당시 확정했던 예약 전체.
- flightPlan: 해당 비행의 전체 명령 기록.
- appliedIds: 실제 성공적으로 실행된 명령 ID.
- plan: 실제 실행한 명령만 복사하는 다음 시도용 계획.
- frames: 당시 위치·속도·자세·연료·엔진·남은 단·분리체·천체·부표·충돌 상태.

중단 전에 실행하지 못한 예약도 당시 진행 바에는 남습니다. 다음 계획을 수정해도 과거 계획은 바뀌지 않습니다. 재생 중에는 현재 계획을 읽지 않고 선택한 Trial만 읽습니다. 목표는 완료 여부와 진행률만 녹화하며 내부 판정 창을 프레임마다 복사하지 않습니다.

다시보기는 물리 엔진이나 명령을 다시 실행하지 않습니다. 약 20Hz로 저장한 상태와 명령 적용 순간의 정확한 프레임을 읽고 위치를 보간합니다. 단 분리 때 기준 바닥 위치가 바뀌는 것은 길이 변화로 보정하며 단 수와 점화 같은 이산 상태를 조기에 바꾸지 않습니다. 기록 범위를 넘어서는 시간 이동은 끝 시각에 제한합니다. 원본 기록과 현재 비행을 수정하지 않습니다.

다시보기의 로켓은 불투명도 0.72이며 캔버스에 약한 잡음·스캔선을 덧씁니다. 동작 줄이기 설정은 노이즈 갱신을 멈춥니다. 기본 카메라는 로켓 추적이며 WASD·휠·가운데 드래그로 풀고 C로 추적을 재개합니다.

## 단 분리와 충돌 형태

world/hull.ts의 세계 좌표 기하를 그림, 물리, 재생이 공유합니다. 각 추진단은 0.12u, 탑재체는 0.10u이며 플레이어는 길이를 조절하지 않습니다. 단 수는 개발 에디터의 로켓 구성으로 정합니다. 동체·노즐·색띠·연결부를 render/rocket-sprite.ts로 그립니다. public/assets/rockets에는 같은 렌더러로 만든 3단·2단·1단·탑재체·개별 부스터 투명 PNG와 원점/치수 manifest가 있습니다. 개발 서버를 켠 상태에서 node scripts/export-rocket-assets.mjs로 재생성합니다. 임의 이미지 확대와 물리 크기를 분리하지 않습니다.

분리하면 해당 구간의 바닥은 부스터에 남고 위 로켓의 바닥은 0.12u 앞쪽으로 옮깁니다. 따라서 끝 위치는 이어집니다. 작은 분리 스프링의 상대 속도를 질량비로 배분하여 총 운동량을 보존합니다. 부스터는 자체 상태와 충돌 몸체를 가지며 다음 엔진은 자동 점화하지 않습니다.

행성 판정은 원과 이동 캡슐의 연속 교차입니다. 코끝과 옆면도 접촉하고, 고속으로 행성을 건너뛰어도 잡힙니다. 접촉 뒤 전체 캡슐을 표면 밖으로 분리하며 반동 자세가 변하는 동안에도 다시 바깥쪽으로 배치합니다. 충돌은 한 번의 반동 뒤 실패합니다. 화면 확대는 충돌 형태를 바꾸지 않습니다. 기존 작은 수정 추진 탐사체는 로컬 수직 자세를 유지하고 옆 추진은 병진만 바꿉니다. 다단 로켓의 자세는 예약 방향으로 정합니다.

## 담당 모듈

screens/flight-timeline.ts는 픽토그램·진행 바·계획 입력을 관리하고 world/program.ts는 장치 안내와 명령 목록을 읽습니다. world/replay.ts는 녹화·재생 상태만 관리합니다. world/hull.ts는 충돌과 그림의 크기 계약입니다. 도움말·설정·에디터·판정 언어는 독립 모듈을 유지합니다.

첫 대기권 미션의 기준 계획은 분리/점화 → 상단 전환/제동 → 엔진 끄기 → 안정 비행으로 완료됩니다. 기존 목표 표현식과 조건 조합을 사용하며 특정 미션 이름 분기를 추가하지 않습니다. 자동 검사 성공은 재미를 보장하지 않으므로 초심자 플레이에서 조작 아이콘과 실패 단서를 읽을 수 있는지도 확인해야 합니다.
