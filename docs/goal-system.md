# 범용 목표 블록

목표는 **물리 상태·사건·과거 기록·실제 비행 구간 통계의 논리식**입니다. 엔진은 임무 이름을 검사하지 않습니다.

## 제작 순서

1. 비행체: 주 로켓·탑재체, 분리한 각 단, 천체.
2. 기준 대상: 천체·정거장·게이트·경로·고정 공간.
3. 값: 물리량, 수치, 계산, 순간 기록, 구간 통계.
4. 비교·조합: <·≤·>·≥·=, AND/OR/NOT, 순서, 연속 유지, 한 번 달성, 사건.
5. 목표 활성 시간과 선행 목표.

탑재체의 상대속력·거리 유지와 분리체의 안전 접촉을 AND로 묶을 수 있습니다. 복합 임무 함수를 따로 코딩하지 않습니다.

## 상태와 수식

`metrics.ts`에 물리량 이름·단위·조회 함수가 있습니다. 거리·고도·상대 위치/속도·방사 속도·에너지·각운동량·회전량·이동 거리·연료·질량·동압·밀도·열·접촉 속력 등을 제공합니다.

덧셈·뺄셈·곱셈·나눗셈·절댓값·최소/최대·제곱근·거듭제곱·삼각함수·방향각을 중첩합니다. 기준 천체 GM과 거리를 이용해 `sqrt(2 GM / r)` 같은 비교 기준을 만들 수 있습니다.

위치/속도는 선택 비행체와 대상의 차이입니다. 고정 공간은 원점 (0,0), 속도 0입니다. 에너지는 기준 중심의 이체 근사이며 다체계 전체 에너지를 자동으로 뜻하지 않습니다. 두 운동 천체의 상대 에너지에는 두 GM을 합산합니다.

분리 전의 분리체·파괴된 비행체·없는 기록·0 나누기 등은 미정입니다. 미정 비교를 NOT으로 뒤집어 성공시키지 않습니다. 사건·순서로 의미 있는 순간을 먼저 지정합니다.

## 순간 기록

‘조건 만족 순간 값을 기록’은 조건이 처음 만족될 때 수식 값을 저장하고 고정합니다. 이름은 영문으로 시작하는 영문·숫자·밑줄·하이픈 1~48자이며 목표 내에서 중복되지 않습니다.

이후 ‘특정 순간의 기록’ 값에서 같은 이름을 참조합니다. 여러 값을 동시에 기록하려면 AND로 묶습니다. 기록은 목표별로 분리됩니다. 연관된 기록·후속 판정은 같은 순서 트리에 둡니다.

```text
순서
  1. 접근 구역에 들어올 때
     AND: 속력 → entry_speed 기록
          에너지 → entry_energy 기록
          사용 추진 → entry_budget 기록
  2. 구역에서 나가면서
     AND: 현재 속력 - entry_speed ≥ 요구 증가량
          현재 에너지 - entry_energy ≥ 요구 증가량
          현재 사용 추진 - entry_budget ≤ 허용 추가 추진
          관찰한 최근접 거리 범위 만족
```

이 구성은 특정 미션 종류에 의존하지 않습니다. 기록 순간·대상·값·비교를 바꾸면 다른 접근·분리·감속 임무에 사용할 수 있습니다.

## 구간 통계

관찰할 수식, 증가하는 구간 축, 구간 길이, 연산을 선택합니다.

| 연산             | 의미                                         |
| ---------------- | -------------------------------------------- |
| mean / rms       | 축 변화량으로 가중한 평균 / 제곱 평균 제곱근 |
| min / max        | 관찰 구간의 최소 / 최대                      |
| integral         | 값 × 축 변화량의 합                          |
| change           | 끝 값 - 처음 값                              |
| coverage         | 요구 구간 중 실제 관찰한 비율 (0~1)          |
| fractionPositive | 값 > 0인 구간의 가중 비율                    |

시간 축은 일정 시간, 회전량 축은 바퀴 수, 이동 거리 축은 비행 길이에 맞습니다. 축이 감소하거나 너비가 바뀌면 다시 시작합니다. 현재 순서 단계에서 평가되기 시작한 이후의 **실제 비행**을 관찰합니다.

평균·최소값은 부분 구간에서도 존재합니다. 전체 구간을 요구하려면 `coverage ≥ 0.999999999`를 AND로 넣습니다. 순간 기록 이후 전체 비행의 최소값은 해당 단계에서 시간 축과 최대 임무 시간 너비로 관찰할 수 있습니다.

물리 틱당 한 번 샘플링하고 약 512개 버킷으로 기억을 제한합니다. 합·제곱합·극값·양수 비율을 보존하며 이동창 경계는 부분 버킷의 가중 근사입니다. 구간 길이와 허용 폭을 0.01t 적분 간격보다 충분히 크게 설계합니다.

## 논리와 순서

AND/OR의 모든 자식은 같은 틱에 평가됩니다. 다른 자식의 실패로 기록·유지 타이머가 멈추지 않습니다. 순서는 현재 단계만 평가하며 성공 후 다음 틱부터 다음 단계로 갑니다.

‘한 번이라도’는 달성을 고정합니다. 연속 유지는 조건이 깨지면 시간을 0으로 되돌립니다. 비행 전체에서 금지할 사건은 `NOT(한 번이라도(금지 사건))`처럼 구성합니다.

게이트는 이동 구간과 평면 교차로 판정합니다. 접촉 속력은 실제 닿은 순간의 값을 제공합니다. 물리적으로 위험한 접촉을 목표 조건만으로 안전 접촉으로 바꾸지는 않습니다.

## 저장과 확장

JSON 버전 2의 목표 `condition`이 유일한 판정 진입점입니다. `display`와 아이콘 위치는 안내용입니다. 구 임무 유형 선택기는 없습니다. 버전 1 파일은 변환해야 가져올 수 있습니다. 원래 작업 폴더의 소스는 별도 보관되어 있습니다.

JavaScript나 eval을 실행하지 않습니다. 연산·물리량·참조·기록 이름·수치·복잡도를 저장 전에 검사합니다. 조건 깊이 12, 수식 깊이 16, 목표당 전체 노드 512 한도가 있습니다.

엔진에 없는 현상은 조건만으로 만들 수 없습니다. 먼저 물리 모듈에 구현하고 실제 상태를 조회 함수로 노출합니다. 이후 목표는 같은 블록 언어로 작성합니다.
