# 맵 자동 생성 · 표면 발사 제작 도구

제작소의 **맵 자동 생성**에서 난이도·임무 종류·천체 수·천체 구성·후보 개수(1~12)·목표 허용 폭을 정하고
**후보 생성**을 누릅니다. 모든 새 후보는 행성이나 달 표면의 실제 로켓 발사대에서 시작합니다.
후보를 명시적으로 열기 전까지 현재 초안·선택·탐색 결과는 바뀌지 않습니다.

## 새 배치와 같은 번호 재현

**생성할 때 새 번호 사용**이 기본으로 켜져 있어 반복해서 생성해도 새 번호와 배치를 사용합니다.
이를 끄고 생성 번호와 설정을 같게 하면 같은 물리 배치와 검증 계획을 다시 만듭니다.
UUID는 매번 새로 발급하므로 이전 문서를 덮어쓰지 않습니다. 후보 카드에 실제 사용한 번호와 후보 번호를 표시합니다.
새 번호는 제작할 때만 사용하며, 저장한 스테이지의 실제 재시도 환경은 항상 고정입니다.

## 천체 수와 난이도

천체 수는 **자동(1~3개 섞기) / 1개 / 2개 / 3개** 중에서 난이도와 독립적으로 선택합니다.
행성 3개의 쉬운 임무와 행성 1개의 도전 임무를 모두 만들 수 있습니다.
발사대의 표면 위치, 관측소의 상대 방향과 높이, 시계/반시계 방향, 주변 행성의 위치·크기·중력이 달라집니다.
추가 천체는 실제 중력과 충돌 반경을 가집니다. **천체 구성**에서 다음을 선택합니다.

| 구성                 | 실제 동작                                    |
| -------------------- | -------------------------------------------- |
| 행성들의 중력권      | 서로 다른 위치·반경·중력의 행성              |
| 행성과 공전하는 달   | 부모 행성 주위를 공전하는 달의 표면 출발     |
| 태양과 행성·위성     | 태양 주위를 도는 출발 행성과 선택적인 위성   |
| 블랙홀 주변 탐사     | 작은 충돌 반경의 강한 중력원과 선택적인 위성 |
| 서로 공전하는 쌍성계 | 출발 천체와 두 별, 세 천체의 상호 중력 적분  |

천체 수는 출발 천체를 포함한 총수입니다. 쌍성계는 3개, 달·태양·블랙홀 구성은 2개 이상이 필요합니다.
혼합 생성은 임무와 천체 구성을 고정 짝으로 묶지 않고 생성 번호와 배치 순서를 교차해 고릅니다.
달·태양계의 지정 공전은 기존 circular motion, 쌍성계는 기존 dynamic body 모델을 사용합니다.
블랙홀은 이 게임의 뉴턴 중력 모델이며 상대론이나 새로운 물리 엔진은 추가하지 않습니다.

각 추가 천체는 검증 비행에서 중력 크기 표본 합의 8% 이상을 기여해야 합니다. 그 천체의 GM만 0으로 만든 비교 비행에서
같은 계획이 실패하거나, 일치하는 시각의 경로 차이가 출발 천체 반경의 0.08 이상이어야 합니다.
추가 천체 전체를 끈 비교도 실패하거나 경로 차이가 0.35반경 이상이어야 합니다.
표시할 다른 풀이도 같은 검사를 통과해야 남깁니다. 카드의 **난이도 추정과 검사 결과**에서 천체별 결과를 볼 수 있습니다.
이 검사는 주어진 계획의 중력 의존성을 확인하며, 모든 가능한 풀이에서 모든 천체가 필수라는 증명은 아닙니다.

| 선택 | 우선 만드는 형태                                         | 근처 조작 변경 성공 기준 |
| ---- | -------------------------------------------------------- | ------------------------ |
| 쉬움 | 가까운 관측소, 짧은 상승이나 완만한 호, 넉넉한 오차 여유 | 6개 중 4개 이상          |
| 보통 | 발사대에서 옆으로 휘는 호와 관측소의 상대 배치           | 6개 중 2개 이상          |
| 도전 | 행성을 크게 감싸는 호와 정교한 출력·종료 조절            | 6개 중 1개 이상          |

난이도는 행성 수를 점수에 직접 더하는 방식이 아닙니다. 실제 성공 비행의 기록에서 행성 주위를 진행한 각도,
발사대 바깥 방향에서 초기 추진 방향을 틀어야 하는 정도, 목표의 상대 높이, 출발점·관측소에서 주변 중력의 상대 영향,
출력·방향·종료 시점 변경의 성공 비율을 함께 사용합니다.
관측 임무의 제작용 점수는 경로 굽음 45점·출발 정렬 15점·상대 높이 10점·주변 중력 10점·조작 정밀도 20점의 합입니다.
30점 이하는 쉬움, 30점 초과 55점 이하는 보통, 55점 초과는 도전이며 위의 조작 여유 기준도 함께 통과해야 합니다.
목표 난이도에 맞지 않는 후보는 제외합니다. 검사 실패에 맞춰 목적지나 허용 폭을 나중에 바꾸지 않습니다.

이 수치는 **제작용 추정**입니다. 한 검증 계획 주변의 유한한 표본을 검사하므로 다른 쉬운 풀이가 없다는 증명이나
사람의 체감 난이도 인증이 아닙니다. 실제 플레이를 보고 난이도를 조정해야 합니다.

## 임무와 로켓

- **상공 관측소 방문**: 표면 발사대에서 출발해 미리 배치된 관측소에서 엔진을 끈 상태로 자료를 수집합니다.
- **연속 관측소 방문**: 떨어진 두 관측소를 번호 순서대로 방문하며 엔진을 끈 상태로 자료를 수집합니다.
- **상승 후 안전 착륙**: 초반 3특성시간 안에 미리 정한 고도 이상 상승하고, 역추진 후 실제 안전 접지와 엔진 종료 상태를 유지합니다. 처음부터 지상에 있거나 늦게 이륙하는 계획은 완료되지 않습니다.
- **엔진 종료 후 한 바퀴 궤도 유지**: 미리 정한 반경 띠에서 엔진을 끄고 실제 한 바퀴를 돌아야 합니다. 잠깐 영역에 들어가는 비행은 완료되지 않습니다.
- **천체계 중력권 탈출**: 모든 천체에서 4반경 이상 멀어지고 바깥으로 움직이며, 전체 중력 퍼텐셜과 질량 중심 속도를 기준으로 양의 에너지를 확보합니다. 연료 20% 이상과 엔진 종료, 표시된 방향 허용 폭도 유지해야 합니다.
- **여러 임무 섞기**: 관측·착륙·궤도·탈출·연속 관측을 차례로 검사합니다. 기본 선택입니다.
- **관측 임무 섞기**: 두 관측 종류를 번갈아 제안합니다. 같은 종류 안에서도 표면 위치·상대 거리·경로 굽음·행성 배치가 달라집니다.

`launchBodyId`, `launchAngle`, 기존 `syncLaunch`를 사용합니다. 로켓은 표면 속도(공전 천체는 그 공전 속도 포함)에서 시작하며
`createRun`은 지상 지지 상태에서 실제 출력으로 이륙합니다. 초기 궤도 속도를 몰래 주거나 발사 뒤 위치를 옮기지 않습니다.
단일 추진단의 기존 연료 소모·회전 속도·충돌 판정을 그대로 사용합니다. 초기 출력과 0초 방향 설정 뒤 엔진 종료 한 번을 예약하며,
이를 기준 비행으로 삼아 출력 조절·중간 방향 수정·끄고 재점화하는 별도 풀이도 찾습니다.
새 로켓은 최초 점화를 포함해 3번까지 점화할 수 있습니다. 명령 한도는 출력 설정 4회·엔진 종료 3회·방향 설정 4회이며,
순간 수정 추진·단 분리는 사용하지 않습니다. 공통 물리 엔진과 기존 문서의 명령 한도는 바꾸지 않습니다.

목적지와 행성 배치를 먼저 고정한 뒤 유한한 초기 출력·방향·종료 시점 조합을 기존 엔진으로 시험합니다.
성공 비행의 끝점으로 관측소를 옮기지 않습니다. 영역 판정과 엔진 꺼짐을 공통 Condition/Expression으로 조합하고
연속 임무는 sequence로 연결합니다. 미션 이름별 물리/판정 분기는 없습니다.
미리보기에는 발사대·천체·관측소와 미리 정한 궤도 띠·탈출 경계를 표시하며, 정답 방향이나 미래 경로를 그리지 않습니다.

착륙·궤도·탈출의 난이도는 안전 접지 속력·허용 궤도 폭·탈출 방향 폭의 부담(최대 45점, 탈출 40점)에
출발 정렬 부담(최대 15점), 실제 조작 오차 실패 비율(25점), 3단계를 넘는 조작마다 3점, 주변 중력 영향(최대 8점)을 더합니다.
JSON을 가져와도 저장된 점수를 믿지 않고 실제 조건과 비행에서 다시 평가합니다.
새 임무는 다단계 상승·관성 비행·궤도 삽입·착륙 역추진 정책을 유한하게 시도합니다.
모든 천체 구성·임무·난이도의 조합에서 후보를 찾는다고 보장하지 않으며, 한도 안에 성공과 조작 여유를 확인한 후보만 표시합니다.

## 자동 생성의 추가 설정 · 조작 숙달 묶음

기존 제작소의 장면·기체·판정 분류와 지도·속성·시험 비행 화면을 유지하고, **맵 자동 생성** 안에만 추가 설정을 제공합니다.
**추가 설정 · 조작 숙달 묶음**을 펼쳐 **조작 숙달 묶음 만들기**를 켜세요. 기본은 꺼져 있습니다.
묶음 수 2~4개와 묶음당 스테이지 수 2~3개를 정하면 총 4~12개를 만듭니다. 기본 설정은 3묶음 × 2개입니다.
숙달 묶음은 관측 임무를 바탕으로 구성합니다. 여러 임무 섞기를 골라도 관측을 사용하며, 착륙·궤도·탈출을 직접 고른 경우에는 묶음을 끄도록 안내합니다.
켜진 동안 일반 후보 개수 대신 두 설정의 곱을 사용합니다. 끄면 기존 후보 생성·쉬운 순서 선별 방식으로 돌아갑니다.

| 묶음 | 새로 연습할 조작         | 검증 풀이에서 함께 사용할 이전 조작    |
| ---- | ------------------------ | -------------------------------------- |
| 1    | 발사·방향 설정·엔진 종료 | 기본 조작부터 시작                     |
| 2    | 출력 조절                | 발사·방향 설정·엔진 종료               |
| 3    | 중간 방향 수정           | 기본 조작 + 출력 조절                  |
| 4    | 끄고 회전한 뒤 재점화    | 기본 조작 + 출력 조절 + 중간 방향 수정 |

묶음 안에서는 **도입 연습 → 다른 배치 응용**, 3개일 때는 가운데 **반복 연습**을 추가합니다.
전체 회전이나 크기만 다른 맵은 별도 배치로 세지 않습니다. 중간 회전·재점화 조합은 기존 엔진에서 실제 성공하고,
앞서 배운 추가 조작 각각을 빼면 실패하는 계획만 연습용 풀이로 남깁니다. 조작 수만 늘린 예약은 제외합니다.
이는 해당 계획에서 조작의 역할을 확인하는 유한한 검사이며, 다른 모든 쉬운 풀이가 없다는 증명은 아닙니다.

자동 생성 안의 후보 모음에 묶음별 목표·복습할 조작·준비된 개수를 표시합니다. 같은 후보를 두 묶음에서 재사용하지 않으며,
앞 묶음의 연습 후보가 부족하면 뒤 묶음을 먼저 채우지 않습니다. 여러 묶음에 맞는 후보는 재배치해 뒤 묶음의 유일한 후보를 앞에서 소모하지 않게 합니다.
이 모드에서는 경로 모양의 점수 한 줄보다 조작의 선행 조건을 우선합니다. 쉬운 배치에서 기본과 출력 조절을 먼저 다루고,
보통 배치에서 중간 회전·재점화의 누적 조합을 검사합니다. 묶음 사이에 추정 점수가 낮아질 수도 있습니다.

**순서 묶음 내보내기**는 기존 `workshop-course` 형식에 `mastery.version: 1`, 설정, 순서별 그룹 ID와 안정된 식별자 키의 그룹 정보를 덧붙입니다.
각 스테이지 사본에는 기존 `chapter` 표시 정보와 전체 `order`를 붙입니다. 원래 후보는 바꾸지 않습니다.
가져올 때 설정을 복원하지만 저장된 성공·숙달 주장은 사용하지 않고 실제 비행과 조작 구성을 다시 검사합니다.
묶음 설정과 후보는 현재 창의 메모리에 있으며 JSON 내보내기로 보관합니다. 플레이어 개인정보나 신규 서버 저장은 없습니다.

사용자가 선택한 범위는 **제작용 묶음 구성과 연습 순서**입니다. ‘연습 후보 준비됨’은 사람이 숙달했다는 판정이 아닙니다.
플레이어의 실제 숙달 추적·다음 묶음 잠금·자동 해금은 추가하지 않습니다. 이미 배운 조작을 플레이 계획에 정답으로 삽입하지도 않습니다.
묶음 생성은 최대 180초를 배치 경계에서 확인하며, 조합 풀이 추가 검사는 배치당 100개까지입니다. 중지·닫기 때 Worker를 종료합니다.

## 여러 풀이를 비교하는 방법

후보의 **풀이 비교**는 기준 비행 외에 다음 방식을 유한한 조합으로 시도합니다.

| 방식                       | 조작 흐름                                            | 보통 단계 수 |
| -------------------------- | ---------------------------------------------------- | ------------ |
| 한 번 올리고 관성 비행     | 초기 출력·방향 설정 → 엔진 종료                      | 3            |
| 출력을 나눠 올리기         | 낮은 초기 출력 → 출력 증가 → 엔진 종료               | 4            |
| 고도를 올린 뒤 방향 바꾸기 | 초기 상승 → 중간 방향 수정 → 엔진 종료               | 4            |
| 끄고 회전한 뒤 짧게 재점화 | 상승 → 엔진 종료 → 관성 중 회전 → 재점화 → 최종 종료 | 6            |

출력은 10% 단위, 시각은 0.1초 단위, 방향은 발사대 바깥 방향에 대해 5도 단위로 시험합니다.
추가한 조작은 하나씩 생략해 실패하는지 확인하므로 조작 수만 늘린 계획은 별도 방식으로 남기지 않습니다.
모든 명령이 성공 이전에 실제로 실행되었는지도 확인합니다. 같은 물리 계획과 이미 찾은 방식의 중복을 제거합니다.
기준 비행도 처음 확인한 성공 조합이지 최소 연료·최소 단계 최적해가 아닙니다.

비교 창은 각 방식의 단계 수·둥근/세밀한 수치 여부·주변 조작 변경의 성공 비율을 보여 줍니다.
선택할 때마다 현재 스냅샷을 기존 엔진으로 실제 실행하고, 완료된 기록을 재생하거나 시간 손잡이로 확인합니다.
초기 출력과 회전 방향도 조작 목록에 표시합니다. 저장된 초안은 풀이 탐색 칸의 **저장된 검증 풀이 N개 비교**로 다시 엽니다.
제작용 비교 창에서만 기록을 보며 플레이 계획이나 본게임 화면에는 정답을 넣지 않습니다.

검사하지 않은 풀이가 더 쉬울 수 있습니다. 둥근 수치가 사람에게 직관적이라는 보장은 없으며, 실제 사람의 플레이로 확인합니다.

## 후보 모음과 학습 순서

**학습 순서용 후보 생성**은 선택 난이도 대신 쉬움·보통·도전을 나누어 만듭니다. 행성 수와 임무 종류 설정은 유지합니다.
쉬운 도입과 연속 관측, 곡선 경로, 큰 우회 사이의 중간 배치를 먼저 준비하고 목적지를 고정한 뒤 성공 풀이를 검사합니다.
일반 **후보 생성**은 기존처럼 선택한 난이도만 만듭니다. 두 버튼의 결과 모두 아래 후보 모음에 누적됩니다.

선별 점수는 앞의 생성 난도 점수와 구별합니다. 둥근 수치 풀이 중 가장 낮은 부담 점수를 사용하며,
`생성 점수 × 0.55 + (1 - 주변 성공 비율) × 24 + min(단계 수, 10) × 2 + 추가 조작 개념 수 × 4 - min(서로 다른 방식 수 - 1, 2) × 2`를
0~100으로 제한하고 반올림합니다. 단계 수만으로 난도를 결정하지 않으며 여러 방식의 여유를 함께 봅니다.

현재 선별 기준 버전은 2입니다. 이전 묶음도 가져올 수 있으며 현재 조건으로 다시 검사합니다.

1. 단일 추진단 표면 발사의 관측·착륙·궤도·탈출 임무를 자동 순서 제안 대상으로 삼습니다. 다른 임무는 직접 검토합니다.
2. 서로 다른 둥근 수치 풀이가 2개 이상이며, 한 방식 이상의 주변 조작 변경 성공 비율이 25% 이상이어야 합니다.
3. 첫 단계는 추가 개념 없이 시작하고, 선택 방식의 주변 변경 성공 비율이 50% 이상이어야 합니다.
4. 이후 점수는 내려가지 않고 한 번의 상승 폭은 22점 이하입니다. 새 개념은 한 단계에 하나까지 추가합니다.
5. 안전 착륙·궤도 유지·중력권 탈출·연속 관측·휘어진 경로·긴 우회와 출력 조절·중간 방향 수정·재점화를 구별합니다. 선택할 풀이가 이미 배운 개념과 어떻게 이어지는지 확인합니다.
6. 비슷한 경로 형태와 관측소 수 조합은 두 개까지 우선 선별합니다. 같은 점수 근처에서는 이후 단계를 열어 주는 개념과 넉넉한 조작 여유를 우선합니다.

표에는 점수·선별 이유·검토할 풀이를 표시합니다. 요청 개수는 1~12개이며, 부족한 입문·중간 단계를 억지로 채우지 않습니다.
모든 후보 비교에서 포함/제외를 직접 선택하거나 다른 배치를 더 생성할 수 있습니다. 보류 이유도 함께 표시합니다.

모음은 현재 창의 메모리에 최대 48개를 유지합니다. **후보 모음 내보내기**는 보류 후보도 보관하고,
**순서 묶음 내보내기**는 선별한 사본만 `order: 1, 2, …`와 `published: false`로 내보냅니다.
원래 후보의 순서는 바꾸지 않습니다. 표의 **초안으로 열기**도 사본에 해당 순서를 붙입니다.
**모음 비우기**는 한 번 취소할 수 있습니다. 창을 닫기 전 JSON으로 보관하세요.

**후보 JSON 가져오기**는 단일 편집 스테이지 또는 이 도구의 두 묶음 형식을 받습니다(5MB·48개 이하).
저장된 점수나 성공 주장을 믿지 않고 현재 스냅샷에서 계획·조작 여유를 다시 검사합니다. 잘못된 형식이면 기존 모음을 유지합니다.
검사는 별도 Worker에서 진행하고 중지할 수 있습니다. 서버 데이터와 공개 목록을 자동으로 수정하지 않습니다.

## 검사와 한도

- 형식·명령 한도·실제 성공, 출발 출력/엔진 종료/필요한 방향 설정의 생략 실패를 확인합니다.
- 초기 출력의 상대 ±5%, 초기 방향 ±3도, 종료 시점 ±특성시간의 4%를 한 변수씩 바꾼 6개 표본을 시험합니다.
  특성시간은 √(출발 행성 반경³ / GM)입니다. 모든 변수를 동시에 바꾼 전 범위 검사가 아닙니다.
- 여러 조작 풀이에는 추가 출력·방향·시각도 한 변수씩 바꿔 검사하며, 명령 순서가 바뀌거나 불법인 표본과 같은 표본은 제외합니다.
- 초기 출력·방향·종료와 출력 조절·끄고 회전한 뒤 재점화를 섞은 임의 계획 16개를 별도로 시험합니다.
  후보에는 기존 감사 설정(표본 32개·허용 비율 15%)도 보관합니다. 현재 공개는 제작소의 기존 성공 기록 재검증 절차를 따르며,
  생성기의 임의 표본 통과를 새로운 공개 조건으로 추가하지 않습니다.
- 관측소 두 곳의 영역과 추가 행성이 서로 겹치지 않게 배치합니다. 단순 크기/시간 배율·전체 회전만 다른 후보는
  다양성의 근거로 세지 않고, 목표의 상대 각도·높이·관측소 수·상대 행성 배치로 비슷한 후보를 묶습니다.
  전체 풀이 전략의 동등성 검사까지 수행하는 것은 아닙니다.

요청 개수의 최대 8배 배치와 실행 경과 약 45초(다중 천체·학습 순서용·새 임무·다양한 천체 구성은 120초, 숙달 묶음은 180초)를 한도로 합니다. 각 배치에서 최대 270가지 초기 조작과
성공 계획 주변의 표본, 여러 풀이 정책 최대 250조합(새 임무는 80조합)을 시험할 수 있습니다. 새 임무의 준비 계획 검사는 배치당 약 240회로 제한합니다. 준비 비행도 화면의 검사 횟수에 포함합니다.
가져오기는 저장된 계획 최대 8개·각 계획의 엔진 명령 최대 12개를 확인하고 추가 정책 최대 160조합을 시도합니다.
시간은 개별 배치 경계에서 확인하므로 한 번의 유한한 검사 묶음이 끝날 때까지 초과할 수 있습니다.
별도 Worker에서 실행하며 중지/닫기/화면 전환/해제 시 종료합니다. 확인된 후보만 남기고 부족한 개수를 불가능한 맵으로 채우지 않습니다.
범용 전체 성공 예약 역산과는 별도의 제작 도구입니다.

## 보관과 공개

후보는 현재 제작소 창의 임시 메모리에 있습니다. **초안으로 열기**는 기존 초안을 이 기기 보관함에 먼저
보관하는 기존 문서 경계를 사용합니다. 보관 실패 시 현재 문서를 교체하지 않습니다.
**JSON 내보내기**는 새 UUID를 파일명으로 한 편집 문서를 내려받습니다. 검증 계획은 제작용 referencePlans에만
포함되고 기존 플레이 배포에서는 제거합니다. 자동 서버 저장·자동 공개·기존 UUID 파일 변경은 없습니다.
서버 저장과 **검사 후 게임에 추가**는 기존 제작소 절차를 사용합니다.
Git 파일 모드의 저장 경로는 기존 data/stages 및 data/releases입니다.

이미 저장된 과거 원 궤도 출발 스테이지는 수정하지 않습니다. 이번 변경은 새 후보 생성에만 적용합니다.
