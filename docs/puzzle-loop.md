# 관측으로 좁혀 푸는 퍼즐

## 진행 규칙

1. 처음에는 목표 위치와 제작자가 제공한 짧은 단서를 읽습니다. 정답 추진값과 미래 궤도는 보지 못합니다.
2. 실제 발사를 해 목표에 못 미쳤는지, 지나쳤는지, 도착했지만 너무 빠른지 관측합니다. 실패도 기록으로 남습니다.
3. 이전 실제 조작을 복사합니다. 방향을 고정하고 추진 세기만 바꾸거나, 같은 접근에서 제동 시각만 바꿉니다. 여러 변수를 함께 바꾼 기록에는 원인을 단정할 수 없다는 안내가 붙습니다.
4. 실제 경로를 겹치고 시간 눈금을 움직여 같은 시각을 비교합니다. 움직이는 천체·정거장도 실제 기록 시각의 위치를 점선 표식으로 함께 봅니다. 기록이 끝난 뒤 위치는 예측하지 않습니다.
5. 조건을 좁힌 뒤 제한된 수정 추진·엔진·단 분리로 미션을 완성합니다. 목표 판정의 수식은 제작자에게만 보입니다.

첫 미션은 첫 추진 1.20의 낮은 도달과 1.40의 지나친 도달을 실제로 관측한 뒤 1.36으로 좁히고, 실제 높이 전환점에서 작은 진행 방향 추진을 7회 사용하면 성공합니다. 이 수치는 회귀 검증 예시이며 플레이 화면에 정답으로 제공하지 않습니다. 2.5%씩 세기를 조절하고 한 번씩 유료 추진을 하는 게임 조작만으로 재현됩니다. 다른 근처 풀이도 허용하는 띠와 한 바퀴 통계로 판정합니다.

## 개발자가 만드는 에디터

개발 서버의 `/?editor=1` 전용 제작 화면입니다. 천체·표면 발사대·대기·움직이는 정거장·상호 중력·경로·게이트·위험 지역·로켓 단과 임의 목표 블록을 조합합니다. 빈 공간 드래그 영역 선택, Shift 다중 선택, 묶음 이동, Ctrl+A/C/V/D, 실행 취소, 장면 목록 선택과 선택 위치 이동을 지원합니다. 복사 묶음을 다른 스테이지에 붙이면 내부 UUID 참조도 연결합니다. 선택 밖 참조는 남으므로 검사해야 합니다.

스테이지 규칙의 **퍼즐 단서 · 실제 관측 설계**에서 처음 단서, 관측 물리량/계산, 측정 조건, 최소/최대/마지막 값 집계, 안내 범위와 낮음/근처/높음 문구를 편집합니다. 상황 단서는 기존 공통 조건 언어로 발생 시점을 정하며 처음 감지 시 정지할 수도 있습니다. 임무 종류별 코드를 추가할 필요가 없습니다. 조건·관측은 별도 메모리에서 평가하므로 단서가 성공 판정을 바꾸지 않습니다.

상황 정지는 최초 감지한 물리 스텝에서 멈춥니다. 실제 비행을 관측한 결과이며 무료 시험 비행이 아닙니다. 정지 중 작은 추진 버튼도 실제 수정 예산을 사용하며, 복사 가능한 실제 조작으로 기록됩니다.

F5로 게임을 시험하고, 돌아와 설계를 고친 뒤 JSON 초안 저장/내보내기/가져오기로 협업합니다. 목표·관측 설계와 장면이 모두 `data/stages/<UUID>.json`에 담깁니다. Git으로 리뷰하며 제작 모듈과 파일 저장 API는 개발 빌드에서만 작동합니다.

## 제작 검사

성공 경로, 무조작/직진 등 단순 전략, 무작위 조작 표본을 검사합니다. 관측을 정의한 문제는 기준 풀이의 세기 ±2%와 추진 시각 ±0.15초를 교차 시험하며, 다른 첫 추진의 안내가 구분되는지도 표시합니다. 희귀한 성공률 자체가 좋은 퍼즐을 뜻하지 않습니다. 넓게 허용하되 한 번 스치기와 다른 궤도를 구별하고, 실패에서 다음 실험을 고를 수 있는지 직접 확인해야 합니다.

현재 8개 미션에 관측 문구가 들어 있습니다. 첫 미션의 세 번 실험 진행은 엔진/브라우저 검증 대상입니다. 모든 고급 미션의 초심자 난이도와 재미를 보장했다고 주장하지 않습니다. 실제 초심자 플레이 피드백으로 단서와 실험 예산을 조정해야 합니다.
