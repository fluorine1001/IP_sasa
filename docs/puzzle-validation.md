# 제작과 반례 검사

1. 플레이어가 이해할 수 있는 목표 문구를 정합니다. 수식은 제작자의 판정에 둡니다.
2. 출발 천체·표면 위치·중력·대기·경로·게이트를 배치합니다.
3. 비행체·기준 대상·물리량·기록·통계·순서를 조합합니다.
4. 실패에서 무엇을 읽을지 관측·상황 단서를 만들고 F5로 직접 시험하고 ‘개발 · 판정 관찰’에서 값·기록·유지 시간을 확인합니다.
5. 성공 명령을 기준 경로로 보관합니다. 조금 어긋난 해와 실패도 시험합니다.
6. 자동 검사에서 단순·임의 전략과 성공 반례를 재생합니다.
7. 원치 않는 성공 원인을 좁히되 근거가 같은 비슷한 해까지 제거하지 않습니다.
8. 서로 다른 실패 안내와 근처 풀이의 조작 여유 검사를 읽고 게임에 추가합니다. 랜덤 변형은 필요하지 않습니다. 초안 파일은 캠페인에 나타나지 않습니다.

## 적절한 허용 폭

순간 접촉만으로 성공하지 않도록 거리·상대속력·순서·시간을 함께 고려합니다. 정확히 한 수치만 맞추게 강제하지 않습니다.

현재 궤도 임무는 표시된 넓은 거리 띠에서 한 바퀴를 완성하고 그 바퀴의 90% 이상을 띠 안에서 비행하는 하나의 결과를 판정합니다. 전체 바퀴의 관측을 coverage로 확인하며 방향 왕복을 더하는 angularTravel 대신 순 회전량 orbitTurns를 사용합니다. RMS·에너지·복수의 정밀 비율 조건을 동시에 맞추게 하지 않습니다. 사용자 정의 통계 블록은 삭제하지 않아 제작 자유도는 유지합니다.

근처 풀이 검사는 초기 출력뿐 아니라 실제 예약 시각(±0.25초), 출력(±5%p), 방향(±5°)을 한 변수씩 바꿉니다. 같은 시각의 묶음 명령은 순서를 보존하고, 포화 출력·불법 계획·중복 표본을 제거합니다. 절반 이상 실패하면 배치·자원·목표 여유의 재검토 경고를 표시합니다. 이 경고는 모든 변수가 서로 같은 난이도라는 증명도, 직관적 풀이를 보장하는 인증도 아닙니다. 현재 일부 본편에 경고가 남으므로 초보자의 실제 실험 과정으로 추가 조정해야 합니다.

순간 기록과 이후 값의 비교로 추진·중력 상호작용의 효과를 구별할 수 있습니다. 분리체와 탑재체를 AND로 묶으면 하나만 성공한 경우를 막습니다. 전체 관찰 구간을 요구할 때는 coverage 조건도 넣습니다.

## 검사 의미

검사는 같은 엔진으로 무작위 초기 추진·일부 수정 추진을 시험합니다. 연료 모델에서는 엔진 방향·스로틀·분리 시점도 바꿉니다. 고정 시드로 재현 가능하며 16~2048개 표본을 사용합니다.

배포 버튼은 구조 오류·기준 성공 경로 부재·허용치 이상의 임의 성공·단순 전략 성공을 차단합니다. 입문 문제에 단순 해가 의도된 경우 팀 리뷰로 검사 정책을 조정해야 합니다.

0%는 우연 성공 불가능의 증명이 아닙니다. 재미와 직관적 풀이 가능성은 직접 플레이로 확인해야 합니다. 유일해를 요구하지 않습니다.
