# 재시도 자동 변형

일반 플레이는 저장된 검증 변형을 중복 없이 추첨합니다. 한 시도의 물리 환경은 비행 중 바뀌지 않습니다. 재시도 때 현재 관측·실제 궤적·추진 예약·부표 예약을 버리고 새 환경의 발사대 측정으로 시작합니다. 새로 입장하거나 발사 기회를 모두 쓴 뒤 새로 시작하면 별도 추첨 세션입니다. 물리 법칙을 이해한 경험까지 없애는 것은 목적이 아닙니다. 과거 수치와 명령의 그대로 재사용을 막습니다.

## 자동 제작 흐름

1. 제작자가 천체와 공통 목표 블록을 만듭니다.
2. F5 실제 시험에서 한 번 이상 클리어합니다. 성공 명령이 기준 경로로 저장됩니다.
3. 수정 후 검사 Worker가 목표식의 길이·시간 차원을 전파합니다. 산술, 순간 기록, 구간 통계, 시간 유지 조건을 함께 분석합니다.
4. 길이 0.75–1.35배, 시간 0.70–1.45배 범위에서 후보를 탐색합니다. 그 안에서 문제에 실제로 통과한 범위만 저장합니다. 중력은 L³/T², 속력은 L/T, 추력은 L/T², 궤도 주기는 T에 맞춰 연동합니다. 밀도·면적·대기 높이·목표 임계값·발사대 여유도 같이 변형합니다.
5. 천체별 중력 크기를 최대 약 ±17%로 추가 변화시켜 봅니다. 정밀 문제는 ±2.5%나 관계를 보존하는 변화부터 시도합니다. X/Y 축에 고정한 목표는 회전하지 않습니다.
6. 각 후보에 변형된 기준 명령을 실제 엔진으로 실행합니다. 실패한 후보는 제외합니다. 모든 이전 변형의 성공 명령을 그대로 실행해 성공하는 경우도 제외합니다. 현재 발사대의 실제 중력 크기가 다른 변형과 최소 약 12% 차이 나는지 확인합니다.
7. 변형별 단순 전략과 64개의 임의 명령 표본을 검사합니다. 임의 성공이 발견된 후보도 제외합니다. 발사 기회 이상의 서로 다른 변형을 확보해야 자동 적용합니다. 기본 최소 6개, 최대 24개입니다.

에디터 하단에서 생성 상태, 보류 이유, 적용 길이·시간 범위, 재사용·임의 명령 검사 횟수를 읽습니다. ‘랜덤 재시도 시험’은 실제 플레이와 같은 추첨과 초기화를 사용합니다. ‘F5 시험’과 ‘기준 경로 재생’은 원본 문제에서 진행하므로 변형 세계의 성공 명령을 원본 기준 경로로 잘못 저장하지 않습니다.

물리·목표·기준 명령을 바꾸면 원본 지문이 달라져 기존 변형을 폐기하고 다시 생성합니다. 자동 변형을 확인하기 전에는 게임에 추가하지 않습니다. 풀이가 없는 초안, 단위가 모호한 식, 지나치게 넓은 목표, 기존 명령이 계속 통하는 문제에는 임의 설정을 붙이지 않고 보류 이유를 보여줍니다.

## 검증과 범위

`npm run generate:variations`는 게임 소스의 변형을 다시 생성합니다. `npm run audit:stages`는 원본뿐 아니라 저장된 모든 변형에서 성공 경로, 다른 변형의 명령 재사용, 단순 전략, 변형당 64개의 임의 명령을 다시 검사합니다.

이는 제한된 후보 탐색과 실제 실행 검증입니다. 임의의 모든 미션에 대한 자동 풀이 증명이나 모든 과거 관측의 무효화를 보장하는 AI는 아닙니다. 제작자의 기준 성공 경로가 필요하며, 복잡하거나 매우 정밀한 설계에서는 변형 생성이 보류될 수 있습니다. 특정 이전 명령이 우연히 새 문제를 풀 가능성 전체를 증명하지 않습니다. 물리 엔진을 새로 확장한 경우 물리량의 단위 관계도 등록해야 합니다.

대기 가열·손상은 고정 계수를 쓰는 게임 근사라 완전한 상사 변환이 아닙니다. 해당 임무는 변형별 실제 비행 검증으로 걸러냅니다. 열 단위의 변환은 가열 항의 주된 L³·⁵/T² 관계를 사용하며, 해석적 보존을 주장하지 않습니다.
