# 구현 현황과 남은 검증

2026-10-14. 이전 10분 마감 후 사용자의 계속 작업 요청으로 후속 구현을 진행했습니다. 아래는 최신 코드 기준입니다. 이 문서는 유한 자동 검사를 전체 연속 해의 증명이나 초심자 이해도의 증명으로 간주하지 않습니다.

## 이번 범용 판정 보강

지도에 배치하는 공간·궤도·속도·접촉·상태·전후 관측 표식과 동시/OR/순서 연결을 추가했습니다. 형식·범위·구간·대상·메타데이터 및 자원 상한의 정확한 계약은 [판정 오브젝트](mission-objects.md)를 참고하세요. 기존 목록형 예시는 선택적 시작 도구일 뿐 런타임 판정의 미션 분기가 아닙니다. 위성끼리와 주 로켓에 대한 상대 관측을 지원하며 실제 분리 전에는 유효한 측정이 생기지 않습니다. 대표 경로를 선택하면 실제 과거 경로를 강조하고 재생은 별도로 실행합니다.

남은 물리 확장: 탑재 위성 자체 추진, 접촉 도킹/결합, 회수 분리체 재발사, 천체 충돌 병합과 천체를 역으로 끌어당기는 유한 질량 비행체 등은 현 모델에 없습니다. 이 현상이 필요한 미션은 물리·기록·예약·판정 속성을 먼저 추가하고 아래 동일한 검사를 거쳐야 합니다. 임무 이름별 별도 성공 분기나 AI 추정으로 이를 대신하지 않습니다.

## 구현된 핵심

- 모든 조건 만족 해를 동등하게 조사하는 전역 탐색. 가중 DP/rank-unrank, 예약 길이·시간·정밀도 교차 확장, 작은 실행 단위의 상태 보존, 공유 예산과 캐시, 유사도 그룹·대표 경로·한 목록. 새 문서는 천체·기체·목표 없이 시작하며 자유 공간 출발도 지원합니다.
- 차단안에서 특정 ‘의도한 해’ 보존 강제 제거. 다른 발견 해·검증 기록에 미치는 실제 영향 표시.
- 실제 한 바퀴 동안 거의 원형 상태를 유지하는 판정, 연속/시간 비율의 환경 유지, 결과 기반 목표 폼·기체 선택.
- 공통 관제석·시각 출력/방향 편집, 자동 종료 재생·편집 복귀, 지속 배속, 바깥 클릭 닫기, 카메라 드래그, 영역 이음매와 재생 모니터 효과.
- 통합 튜토리얼의 수동 진행·목록 잠금, 크기 제한·읽기 영역·관성 스크롤, 드래그/최소화·강조 모션·열린 계획 창 회피.
- 독립 editor.html, 공유 목록·저장/공개/수정/삭제 API, 편집 키, revision 충돌 방지·복구 가능한 삭제, 공개 목록의 제작 기록 제거, 서버 목록의 게임 반영.

## 남은 작업과 완료 기준

### 0. 비행체 생명주기와 의도적 파괴 임무 — 범용 판정의 다음 필수 보강

현재 주 기체의 파괴·동압/가열 손상·관측 범위 이탈은 비행 전체를 종료합니다.
따라서 주 기체를 잃은 뒤 생존한 위성의 궤도 유지나 부스터 회수를 계속 관측하는 임무,
주 기체의 의도적인 고속 충돌을 최종 성공으로 삼는 임무는 아직 완전하게 지원하지 않습니다.
분리체의 충돌 사건은 파괴 접촉과 안전 착륙을 구분하지만, 주 기체의 안전 완료 규칙은 별도입니다.
이 제한을 “어떤 실제 임무든 이미 모두 지원”하는 것으로 설명하면 안 됩니다.

작업 방법: Run의 시뮬레이션 수명과 각 기체의 alive/landed/destroyed/out-of-range 상태를
분리하고, 물리 스텝에서 접촉·손상·유효 점화 사건의 기체 ID·시각·위치·접촉 직전 속도를
관측 원장에 기록합니다. 판정은 관측 원장을 먼저 검사하고, 현재 위치를 잃은 기체에는
과거 접촉 기록과 미래의 생존 상태를 구분해서 제공합니다. 명시적인 생존 요구는 일반
조건으로 표현하고, 주 기체의 실패가 무관한 독립 기체의 임무를 자동으로 실패시키지 않도록
engine.ts의 조기 종료·tick·updateGoals·replay.ts의 기록과 flight/screen.ts의 종료·추적 대상을
함께 개편해야 합니다. 편집 표식에는 안전 접촉/파괴 접촉 및 판정할 기체를 시각적으로 지정합니다.

완료 기준: 상단 파괴 후 부스터만 안전 회수, 운반체 재진입 뒤 위성 한 바퀴 성공,
선택 위치에서의 의도적 충돌 성공, 잘못된 위치/다른 기체 충돌 실패, 모든 해당 기체를
잃었을 때의 실패 및 녹화/재생 일치. 기존 주 기체 임무의 충돌 실패와 기존 9개 제작 비행도
함께 회귀 검사합니다. 현재 범용 Condition 문법을 그대로 사용하고 미션 이름으로 분기하지 않습니다.

### 1. 실제 퍼즐 조작 여유 확보 — 높은 우선순위

훈련 제작 검증 기록을 거친 값으로 다시 조사해 5% 출력·0.25초·5도 주변 변경 성공을 11/16으로 높였습니다. 물리·장치·실제 거의 원형 한 바퀴 조건은 느슨하게 하지 않았습니다. 플레이 화면에 기록/정답을 제공하지 않습니다. 같은 조작 순서의 변경과 순서를 뒤집는 변경은 이제 따로 보고하고, 변경별 실제 실패 이유도 표시합니다. 본편 2·4·6·7·8에는 조작 민감도 경고가 남습니다. ‘정밀 측정 없이 누구나 풀 수 있음’을 검증했다고 주장할 수 없습니다.

작업 파일: data/stages/34643eaf-0363-4898-b617-63e79ba47d97.json, src/editor/nearby-plans.ts, src/editor/audit.ts, scripts/check-training-margin.mjs.

남은 작업: 초심자에게 정답 수치 없이 직접 실험하게 해 관측→가설→한 변수 변경→해결이 가능한지 확인합니다. 본편은 이후 사람이 제작할 새 스테이지에서도 민감도·실패 구분 검사를 사용합니다. 충분한 조작 여유가 없는 경우 제작자가 전역 해 그룹을 보고 중력·장치·자원·목표 영역을 조정해야 하며 시스템이 특정 해를 의도 여부로 분류하거나 몰래 조건을 완화하지 않습니다.

완료 기준: 충분한 폭의 여러 성공 구간과 구별 가능한 실패 관측, 시간/방향의 소수점 정밀 입력 없이 성공하는 실제 초심자 플레이 기록. 기존 학습 동작과 실제 원형 궤도 조건을 모두 만족해야 합니다.

### 2. 유효해 그룹의 연결성·범위 신뢰도와 성능 확대

현재 그룹은 실제 성공 비행의 유사도 집합이며 전체 연속 성분의 증명은 아닙니다.
예약 길이·시간·정밀도 교차 확장과 긴 비행의 상태 보존/재개는 구현했습니다.
기본 6개/자동 256개/누적 8192회/audit 창의 영구 탐색 제한은 제거했습니다.
유한 임무는 실제 종료 시각까지, 무제한 임무는 확장한 유한 창으로 검사합니다.
중간점 검사와 유사도 그룹, 정확한 계획 중복의 정보는 따로 다룹니다.
구체적인 알고리즘·조건부 점근 전제·비용은 [탐색 알고리즘](search-algorithm.md)에 기록했습니다.

남은 최우선 알고리즘 작업:

1. 판정 AST의 모든 물리량/기록/구간/수량 노드에 건전한 구간 상·하한 계약을 추가합니다.
2. 물리 적분의 오차 포함 구간 상태, 움직이는 천체/동체 충돌과 분리·점화 사건 경계 분할을
   구현하고, 상·하한으로 결론을 낼 수 있는 경우만 영역을 가지치기합니다.
3. equality/경계-only 성공, 불연속적인 접촉 및 무한 반복/무한 시간에 대해 허용할 수 있는
   정확한 판정 의미를 정의합니다. 현재 게임 모델에 대한 증명 없이 일반 이론을 끌어다
   모든 해 보장 또는 전체에 근접한 보장율이라고 표시하지 않습니다.
4. 전체 그룹 차단을 주장하려면 후보 수정에 대해 저장 표본뿐 아니라 그룹의 매개변수
   영역을 위 구간 판정으로 검사해야 합니다. 현 최대 64개 후보/16개 표본은 전수 증명이 아닙니다.
5. 긴 원운동·다중 상호 중력·여러 떨어진 해 영역·좁은 경계 해·분리체 임무의 fixtures와
   Worker heap/취소 지연을 확대 측정합니다. 결과/셀 자체의 장기 메모리 증가도 예산화합니다.
6. 600초 이후 발견된 무제한 임무의 제작 검증 기록을 서버 공개 검사와 연결합니다.
   현재 audit.timeLimit 스키마 상한은 600초, 서버 검사는 120초 wall-clock 제한입니다.
   검사 생략 없이 자동 검사 창/실행 재개 계약을 개편해야 하며 비용/DoS 방어도 유지합니다.

이미 구현된 최적화: 물리 계획 캐시 4096개, 최근 4개 층 DP, 변경된 그룹만 재계산,
매개변수 WeakMap, 실제 경로 재사용·영상은 선택 시 녹화, 비활성 완료 generator 정리,
오프스크린 결과 카드 렌더링 지연, 차단 후보 중복 비행 캐시와 조기 기각.
0.01초 물리와 실제 성공 조건은 유지합니다. 이 최적화는 모든 임무의 유한 실시간 완료
증명이 아닙니다. 최신 성능 수치는 위 알고리즘 문서와 검증 기록을 참고하세요.

완료 기준: 건전한 구간 경계의 모든 노드 회귀 검사, 실제 사건 경계 fixture, 여러
떨어진 성공 영역의 포괄, 동일 예산 비교, 취소/메모리 예산 통과. 전체 실수·무한 시간
완전 판정 또는 거의 전체라는 표시는 증명 없이 추가하지 않습니다.

### 3. 공유 서버 운영 배포와 팀간 왕복 확인

파일/표준 PostgreSQL 저장을 같은 계약으로 구현했습니다. Render Free + Neon Free를 선택했고 기존 Neon 프로젝트를 재사용합니다. 서버의 공개 검사 작업자 격리·인증 실패 제한·UTF-8 청크 읽기·프록시 동일 출처·DB 트랜잭션 충돌/삭제 보존/한 번만 시드는 자동 검사했습니다. 외부 배포 상태와 최종 URL은 docs/verification.md에 별도로 기록합니다.

작업 파일: scripts/serve-workshop.mjs, scripts/workshop-api.ts, src/editor/library.ts, src/stages/live-catalog.ts, src/stages/server-config.json, docs/shared-workshop.md.

남은 운영 검사: 두 독립 clone에서 같은 서버 주소를 설정해 A의 생성/수정/비공개/삭제가 B의 목록 재진입에 반영되는지 확인합니다. 독립 HTTP 클라이언트와 실제 PostgreSQL 엔진에서 revision 충돌·삭제 보존·재저장은 확인했으나 서로 다른 제작자의 실제 인터넷 작업을 대체하지 않습니다. 실제 pg_dump/복원과 무료 호스트의 cold start·120초 검사 제한·용량 한도를 확인합니다. 유료 이전은 DATABASE_URL 교체와 표준 DB 이전으로 가능하며 사용자 승인 없이 업그레이드하지 않습니다.

완료 기준: 두 제작자 동시 수정, 세션 중 환경 고정, 오프라인 fallback, 서버 재시작·백업 복구, 공개 응답의 검증 계획/키 부재를 운영 환경에서 확인합니다.

### 4. 작은 화면의 여러 패널 및 목표 폼 고도화

넓은 화면 자동 배치는 열린 계획 창을 피합니다. 390px에서는 자동 안내를 상단 읽기 선반에 두고 편집/기록 창을 아래에 적층해 실제 예약 버튼을 조작할 수 있도록 했습니다. 직접 드래그한 위치는 발사 패널을 침범해도 사용자의 선택을 존중합니다.

작업 파일: src/screens/tutorial/lesson.ts, lesson.css, src/screens/flight/console.css, src/editor/outcome-inspector.ts, inspector.ts, screen.ts.

완료한 보강: 정형 결과 목표만 전체 AST가 일치할 때 역변환하며 높이/중심거리·유지시간·기체·환경 비율을 보존합니다. 사용자 추가 조건은 재확인 없이 교체하지 않습니다. 읽을 수 없는 임시 초안은 원본 내보내기/명시적 백업 후 교체를 제공하며 자동 덮어쓰기를 막습니다. 회수·분리체 판정과 폼 왕복을 회귀 검사했습니다. 남은 검사: 화면 확대/좁은 높이/입력 장치별 여러 창 조합과 실제 초심자 읽기 평가.

완료 기준: 자동 배치에서 접근할 수 없는 버튼 없음, 휠/키보드/드래그 정상, 폼 재생성으로 반경/높이 단위가 변하지 않음, 일반 조건의 추가 제약을 성공 조건 설명이 숨기지 않음.

### 5. 최종 회귀·문서·개인 브랜치 정리

최신 실행 결과는 docs/verification.md에 기록합니다. Windows에서 Playwright 소유 서버 종료가 멈추는 경우 별도 개발 서버를 E2E_PORT로 재사용합니다. Git diff에는 이전 작업부터 이어진 변경이 있습니다. 사용자가 관련 변경을 codex/free-workshop-deployment 개인 브랜치에 commit/push하도록 승인했습니다. hello.py·사용자 변경을 보존하고 생성물·비밀 값은 제외하며 원격 main 병합/force push는 하지 않습니다.
