# 정확한 역산 집합 연산 연구 — 아직 전체 물리 역산이 아님

## 완성 기준

2026-10-16 최종 사용자 기준: 일반 물리의 전체 성공 예약(종류·대상·순서·연속 시각 포함)을
문제 조건에서 역산하고 유사 해를 그룹화하여 실제 제작소에서 최대 약 1분 내 처리합니다.
발사 표본을 더 많이 검사하는 속도 개선으로 목표를 대체하지 않습니다. 아래 실험은 그 최종 완료가 아닙니다.

사용자가 확정한 목표는 고정 환경 s에서

`S(s) = { p | Legal(s,p) && Execute(s,p).status === 'won' }`

전체를 얻고, 유사한 성공 예약을 그룹화하고, 충분히 짧은 시간에 처리하는 것이다.
예약 p에는 조작 종류·대상·순서·시각·설정값이 모두 포함된다. 실행 중 목표 이력과
물리 사건도 판정에 포함한다. 일부 임무 공식, 성공 표본, 국소 최적점, 실행기 일치,
가능 영역의 상계만으로 이 기준을 통과시킬 수 없다. 시간·공간 비용도 함께 낮춰야 한다.

**현재 위 기준은 미달이다. 아래 구현은 정확한 이산/시간 이론 계층이지 S(s)의 계산이 아니다.**
운영 `global-search.ts` 전체를 교체하지 않았다. 제한된 실제 물리 관계의 성공 영역은
`inverseProjection → searchSolutions`를 통해 실제 비행 재검증 후 기존 풀이 목록에 연결한다.
물리/목표와 연결하지 않은 시간 이론 결과를 성공 비행으로 표시하지 않는다.
UI/서버/스테이지 관리 후속 작업은 이 핵심 요구보다 앞서 진행하지 않는다.

## 이번에 실제 구현한 것

- `decision-set.ts`: ROBDD, 동시 역치환, 관계 곱과 존재 양화의 융합,
  인수별 마지막 사용 시점 변수 소거, 변수 순서 변경, 전체 해 개수, 대표 한 개 추출.
- `time-zone.ts`: 실수 차이 제약의 닫힌 DBM, 정확한 투영과 동시 clock reset 역상.
  binary64 입력 상수를 정확한 이진 유리수로 읽으며 엄격 부등식을 따로 보존한다.
- `weighted-decisions.ts`: 가중 edge-valued DD. 서로 다른 2^N개 값을 N 수준의 공유 노드로
  표현할 수 있는 입력군을 다룬다. 공통 상수 추출, 최댓값 우세 판정, 격자 임곗값 정규화,
  고정된 대표 선택의 공유 DAG 평가를 구현했다. 모든 입력에서 선형 크기라는 뜻은 아니다.
- `timed-choices.ts`: 조건부 시간 제약의 모든 만족 선택을 한꺼번에 구한다. 시간 격자나
  선택 배정 목록을 생성하지 않는다. SCC로 독립적인 순환 문제를 분리한다.
- `timing-elimination.ts`: 음수 순환 검사를 위한 희소 min-plus 변수 소거.
  차수 곱 우선 indexed heap에는 정점당 한 항목만 둔다. 소거 기록의 역대입과 SCC DAG
  한 번의 전파로 대표 시각을 복원한다. 대표마다 다시 V회 완화하지 않는다.
- `symbolic-components.ts`: 대칭 관계의 연결 성분을 BDD 관계상으로 확장한다.
  대표는 성분당 한 개만 꺼낸다. 반환은 지연 generator이며 전체 정점 목록을 만들지 않는다.
- `timing-components.ts`: 동일한 사건 구성의 시간 셀 합집합을 연속 성분으로 분류한다.
  비선형 궤적 유사도나 서로 다른 물리 조작의 동치 판정을 대신하지 않는다.

## 시간 이론의 정확성

입력은 유한한 선택 변수 b와 실수 시각 t에 대한

`allowed(b) AND ∧_i (guard_i(b) => t_left - t_right <= c_i)`

이다. `<`도 허용한다. 출력 `choices(b)`는 이 식을 만족하는 실수 t가 존재하는 b의
정확한 집합이다. 원래 조건부 제약을 같이 유지하므로 대표 시각 외의 모든 시각 해도 남는다.
시간 상한이 없는 입력에 유한한 검사 창을 대입하지 않는다.

정점 v를 소거할 때 u→v와 v→w의 합을 u→w의 상한에 반영한다.
고정된 선택 b에서 이는 t_v의 모든 하한과 상한을 짝지어 비교하는 것과 같다.
유한한 차이 제약에서는 그 비교와 모순인 자기 순환 제거가 t_v의 존재 조건과 동치다.
이 정당성을 각 소거에 귀납 적용한다. 가중 DD는 모든 b에 대해 같은 연산을 점별로
정확히 적용하므로 선택을 하나씩 실행할 필요가 없다.

엄격 부등식은 `정수 + 정수·ε`의 사전식 순서로 계산한다. 유한한 제약에서 원래 엄격
부등식과 동치이며, 대표를 꺼낼 때 실제로 충분히 작은 이진 유리수 ε를 구성한다.
대표를 binary64나 UI 소수 자릿수로 반올림해도 같은 해라는 주장은 하지 않는다.

시간 셀은 볼록하다. 비어 있지 않은 두 셀 C,D의 연결은
`C ∩ closure(D) != empty OR closure(C) ∩ D != empty`로 연결한다.
두 폐포끼리만 만나는 열린 구간의 틈을 연결로 착각하지 않는다. 원래 빈 셀은 먼저
제외해야 한다. 그래야 엄격 순환을 완화했을 때 생기는 가짜 접점을 쓰지 않는다.
두 선택 변수 복사본과 공통 시각 변수로 모든 셀 사이의 접촉 관계를 한꺼번에 역산한다.

## 계산 비용과 실제 실패에서의 개선

V는 시각 수, E는 조건부 간선 수, P는 소거 과정의 `Σ indegree(v)·outdegree(v)`,
F는 추가 간선 수다. DD 연산 비용과 큰 정수 연산 비용을 별도로 계산해야 한다.

- 구조 처리: `O((V+E+P) log V)`. 연산 순서는 희소성을 위한 휴리스틱이며 전역 최적 순서의 증명은 아니다.
- 그래프·소거 기록 공간: `O(V+E+F)`. DD arena/계산 캐시의 메모리는 이 항에 포함되지 않는다.
- 대표 하나 복원: `O(V+E+F+D)` 수준의 산술/선택 노드 처리. D는 그 대표에서 실제 방문하는
  공유 가중 DAG 노드 수다. 가중 노드가 여러 소거 기록에 나와도 한 번 평가한다.
- 그룹화: DD 관계 곱 비용·기호 확장 횟수·출력 성분 수에 의존한다. K개의 대표를 모두
  출력하는 비용은 최소 Ω(K)다. 모든 임무에서 작은 DD나 적은 그룹이 된다는 증명은 없다.

기존 기호 Bellman–Ford와 ID 순서로 구성한 입력군에서 중간 `min` 표현이 폭증했다.
선택 16개에서 65,705노드, 선택 32개에서 500,000노드 한도 초과였다.
한도를 늘리지 않고 제약 상수의 영향도에 따라 선택 변수 순서를 정했다.
이어 V회 반복 완화 대신 희소 소거로 그래프 합성 횟수 자체를 낮췄다.

## 전체 물리 역산에서 반드시 남은 핵심

### 2026-10-15 추가 구현: 실제 비선형 계산과 연결

`physics/nonlinear-kernel.ts`에 중력과 RK4의 산술 프로그램을 분리했다.
`NonlinearRelation`은 같은 프로그램을 관계식 DAG로 컴파일한다. 숫자 실행은 같은
프로그램에서 생성한 `nonlinear-native.ts`를 사용한다. `physics-kernel-source.ts`와
원본/생성 코드 일치 테스트가 공식의 분기를 막는다. 런타임 eval은 사용하지 않는다.

생성 코드는 기존 산술 순서를 유지하고 중력 합산의 중간 벡터 생성을 줄인다.
최초 추상화 구현에서 관측된 2.33배 지연을 그대로 남기지 않았다. 최종 동일 체크섬
5만 스텝/5회 중앙값 비교는 기존18.55ms, 생성 경로17.87ms였다. 단일 로컬 미시 측정이며
모든 게임 배치의 배속 보장이나 전체 역산의 성능으로 환산하지 않는다.

`real-domains.ts`는 닫힌 구간의 합집합을 유지한다. 제곱/곱/나눗셈/세제곱/거리/최댓값
역전파가 갈라진 가지를 하나의 볼록 껍질로 덮지 않는다. 0을 포함하는 분모와
`x*0=0`의 역상을 구별한다. 부모 의존 간선·작업 큐는 목표가 실제 참조하는 부분 그래프에만
만든다. 평가 테이프도 그 조각만 저장하며 의존 순서 계산에서 정렬을 제거했다.

전방/역방향 구간 전파에 더해, 중간값 형식의 구간 뉴턴 수축을 추가했다.
역방향 구간 자동미분으로 모든 제어의 미분을 한꺼번에 계산하고, 다른 변수의 기여 합은
prefix/suffix로 계산한다. 목표 수 M, 관련 DAG 크기 E, 제어 수 P일 때 한 뉴턴 통과의
방문 항은 `O(M*(E+P))`이며 단일 목표의 작업 공간은 `O(E+P)`다. 변수마다 원래 비행을
재실행하는 계산이나 좌표별 잔여 합의 `O(P^2)` 항을 넣지 않았다. 구간 조각 수와 기본
구간 연산 비용은 별도다. 뉴턴 수축과 국소 전파 전체의 수렴 시간 보장은 아니다.

구간 미분은 떨어진 입력 조각의 **전체 볼록 껍질**에서 계산한다. 중간점에서 실제 입력까지
지나는 틈의 미분을 제외하면 잘못된 뉴턴 배제가 되기 때문이다. 결과 입력 구간의 틈 자체는
유지한다. 변수 반복으로 기존 전파가 `[-100,100]`을 줄이지 못하던 사례에서 512개 제어를
약13.6ms에 처리해 유효 변수의 필요 구간을 `[1,2]` 수준으로 줄였다. 이 사례는 의존성
처리 검사이지 512개 조작의 모든 실제 비행을 푼 결과가 아니다.

실제 중력 RK4 한 스텝의 초기 vx/vy·가변 실행 시각에서 최종 속도 영역을 역전파하는
검사는 약9.1ms였다. 별도287개 실제 게임 입력의 위치·속도와 같은 DAG의 수치 실행이
일치하고, 실제 성공 표본을 없애지 않는 것을 검사했다. 제곱의 두 역상, 반복 변수,
다중 제어, 입력 구간의 틈, 무작위 비선형 DAG 100개의 만족점 보존도 검사했다.

```text
npx vitest run tests/nonlinear-kernel.test.ts tests/nonlinear-relation.test.ts
node scripts/research-nonlinear.mjs
```

**아직 contractor이지 전체 성공 예약 solver가 아니다.** 수축된 각 입력의 구간을
곱한 모든 조합이 성공한다는 뜻이 아니며, 관련성은 원래 DAG에 남아 있다.
실수 관계의 구간 증명과 게임의 반올림된 산술의 증명도 동일하지 않다. 현재는 실제 게임
탐색을 이 결과로 배제하지 않는다. 충돌·분리·연료·목표 이력을 포함한 모든 모드의 역상,
성공 영역의 완전 투영과 물리적 그룹화, 전체 예약 구성·순서·시각의 종료 증명이 남아 있다.
다음 목록은 이 변경 이후에도 완료되지 않았다.

1. 실제 게임의 상태 전이와 전체 목표 이력을 공유하는 비선형 이론 계층이 필요하다.
   RK4 중력, 유한 연소, 회전, 질량 변화, 충돌, 착륙, 분리/reset, 이동 천체를 포함해야 한다.
   물리 술어를 서로 독립적인 Boolean 선택으로 두면 거짓 성공이 생기므로 금지한다.
2. 그 비선형 관계에서 연속 상태를 제거해 성공 예약 영역 자체를 계산해야 한다.
   전이식을 식으로 저장하기만 하거나 국소 수반/근 찾기를 호출하는 것으로 대체하지 않는다.
   현재 시간 이론은 그 제거를 수행하지 않는다. float 게임의 경계와 실수 모델 차이도 남아 있다.
3. 그 성공 영역에 대해 실제 조작과 경로의 유사성/연결성을 정의하고 검증해야 한다.
   현재 시간 셀 성분을 실제 성공 비행 그룹으로 표시해서는 안 된다.
4. 실제 제작소의 정답 없는 다양한 원본 입력으로 전체성·정확성·실행시간·메모리를 함께
   검증한 다음에만 운영 탐색을 교체한다. 현재 자료로는 일반 물리 전체 해/10초를 보장하지 않는다.

### 2026-10-15 추가 구현: 충돌·분리·연료·목표 기억의 조건부 관계

`physics/hybrid-kernel.ts`와 `NonlinearRelation`에 물리량으로부터 계산하는
비교/선택 노드를 추가했다. 사건 여부를 자유로운 Boolean 물리 술어로 입력하지 않는다.
동일 식 DAG 안의 조건부 상태로 양쪽 모드를 유지한다. 조작 선택은 제어 변수일 수 있지만,
충돌 여부·연료 소진·점화 허용 여부는 그 제어와 현재 물리 상태의 식이어야 한다.

- 연료 소비량의 min, 질량 변화, 유한 연소의 로그 속도 변화, 연료 소진 후 출력 0,
  출력의 범위 제한, 남은 연료/점화 횟수에 따른 재점화 허용·거절을 구현했다.
- 단 분리 양쪽 속도와 위치 reset은 기존 연산 순서와 운동량을 보존한다. 실제 게임의
  `controlEngine`, `poweredStep`, `separate`가 같은 커널의 숫자 해석을 사용한다.
- 캡슐 sweep 식은 이동 천체 기준의 초기 겹침·정지·접선·끝면·옆면 접촉을 포함한다.
  비활성 후보의 0 나눗셈/음수 제곱근은 안전한 피연산자로 바꾸되 유효 후보 값은 바꾸지 않는다.
  기존 게임 hull 함수는 유지하고 그 결과와 독립 대조한다. 정착 위치/충돌 후 회전까지
  일반 전이로 컴파일한 것은 아니다.
- 성공·착륙·충돌·장애물·관측 모드·종료의 우선순위를 공유 `flightOutcome`으로 만들었다.
  실제 게임도 이 함수를 사용한다. 충돌 중 목표가 참이어도 안전한 착륙이 아니면 성공하지 않는다.

`RocketResources`는 모든 추진단·분리 부스터·탑재 위성의 자원과 reset을 연결한다.
현재 추진단, 각 단의 연료/점화, 부스터의 존재·상태·독립 출력, 위성 중복 분리 거절,
분리 시각/위치/속도, 남은 질량, 실행 종료 상태를 버리지 않는다. 조건부 선택 노드를 사용해
단 분리 이력마다 별도 비행 목록을 복제하지 않는다. S개 단/탑재체와 C개 자원 조작의
컴파일 구조는 `O(S*C)` 크기이며, 이는 모든 실제 미션의 역산 시간 복잡도가 아니다.
회전·열/응력·이동 천체 적분·접촉 후 상태는 아직 상위 비행 컴파일러가 연결해야 한다.

`GoalHistory`는 미션 이름이 아니라 기존 Condition 트리를 컴파일한다. all/any/not,
hold/once/sequence/capture, 참조·의존·시간 창·양화를 처리한다. 알 수 없음을 거짓으로
바꾸지 않고, 선택하지 않은 sequence 자식이나 이미 완료한 목표의 기억을 진행시키지 않는다.
순서 목표는 실제 엔진처럼 한 tick에 한 자식만 진행한다. 참조/양화의 기록 scope도 분리한다.
목표 참조가 기존 목표의 capture 값을 그대로 복사하지 않는다는 실제 동작을 대조 중 확인했다.

이 컴파일러의 metric/event leaf는 실제 물리 관계식을 반환해야 한다. 구간 통계(window),
회전 누적/이동 거리 등 metric 고유 이력, 추가 삼각/타원 계산의 관계는 아직 완성되지 않았다.
extension 없이 지원하지 않는 표현을 만나면 명시적으로 중단한다. 임의 술어 비트나 숫자
샘플을 제공해 이 빈 부분을 완성된 역산처럼 표시해서는 안 된다.

역전파에는 다음 안전장치를 추가했다.

1. min/뺄셈/제곱근/로그/비교/조건부 선택의 필요 영역을 전파한다. 선택된 모드가 확정되면
   해당 자식으로 전파하되, 확정되지 않으면 양쪽 가능 영역을 유지한다.
2. 뉴턴 전파 전에 **입력 합집합의 전체 볼록 껍질**에서 각 guard를 평가한다. 모든 입력에서
   같은 모드임이 입증된 선택의 내부만 미분한다. target을 만족한다고 가정해 guard를 고정하지 않는다.
   연속적인 min/max의 일반화 미분 경계는 유지하되 불연속 선택을 가로지르는 미분은 하지 않는다.
3. 선택하지 않은 부분식에 log(0), sqrt(음수), 0 나누기가 가능하면 그 부분식을 보수적으로
   넓힌다. 무관한 분기를 정의하기 위해 유효한 입력을 잘라내지 않는다. 이 선택은 완전한
   definedness 이론을 대체하지 않으며 수축 강도가 약해질 수 있다.
4. 로그 구간은 Math.log의 오차가 1ulp라고 가정하지 않는다. mantissa를 [1,2]로 줄이고
   atanh 급수 48항과 기하급수 꼬리 상계, 바깥 반올림으로 ln(2)와 log를 감싼다.
   지수 역상 후보도 그 log 구간으로 확인하며 실패하면 넓힌다.
5. 닫힌 구간으로 다루는 strict 비교의 경계는 원래 비교식에 남는다. 입력 구간의 곱을
   성공 집합으로 해석하지 않는다. 관계 DAG 자원 제한은 명시적인 예외이지 빈 집합 증명이 아니다.

추가 검증은 `tests/hybrid-relation.test.ts`에 있다. 1,701개 캡슐 sweep,
연료/재점화 경계·다단/위성 자원 전이·목표 이력·종료 우선순위의 64개 논리 조합,
혼합 조건부 DAG의 만족점 보존을 검사했다. 연결된 연소→적분→충돌→유지 목표→안전 종료
관계에 대해 288개의 실제 비행 성공 여부가 같은 DAG의 수치 실행과 일치하며,
성공 표본이 필요 영역 역산으로 잘려 나가지 않는 것도 검사했다.
이 288개는 유한한 대조 검사이지 전체 연속 성공 집합의 증명이 아니다.

**최신 상태도 전역 성공 예약 집합 계산의 완성이 아니다.** 현재는 필요한 자원/사건/기억
관계를 연결하고 역전파하는 단계다. 모든 Condition metric/window와 전체 engine tick,
연속 예약 시각에 따른 tick 분할·동시 실행 순서, 모든 예약 구성의 관계 생성/상태 제거,
정확한 성공 영역 투영·유사 해 그룹화, IEEE 경계 검증과 짧은 시간 안의 종료 보장은 남아 있다.

배포·서버 데이터·미저장 제작소 문서는 변경하지 않았다.

### 2026-10-15 후속 구현: 구간 통계·성공 영역·실제 제작소 연결

이번 추가분은 `WindowRelation → GoalHistory → inverseProjection → searchSolutions → SearchWorker`
경로로 실제 제작소 탐색에 연결한다. 별도 연구 화면이나 성공 종류를 만들지 않는다.
결과의 대표 예약은 원래 `createRun/tick`으로 확인한 뒤 기존 풀이 목록·예약 그림·영상에 넣는다.
`SearchReport.projection`은 영역 처리 통계일 뿐, 전체 예약 공간의 완료 증명이 아니다.

`physics/window-kernel.ts`는 mean/rms/min/max/integral/change/coverage/fractionPositive의
모든 구간 통계를 컴파일한다. 평가하지 않은 조건, unknown 값, 폭 변경, 역행하는 domain,
같은 물리 시각의 재조회, 마지막 표본 병합, 앞 표본의 비례 잘림, 첫 값·끝 값과 covered를
기존 게임과 같은 순서로 처리한다. 목표/참조/양화 scope마다 큐를 분리한다. 조건부 present
항으로 큐의 수명을 나타내며 이력마다 큐 전체를 복제하지 않는다. 고정된 시각·폭의 죽은
표본은 제거하지만, 수명이 제어에 따라 변하면 T회 호출의 그래프 구성이 최악 O(T²)일 수 있다.
`constant-kernel.ts`의 제어 독립 항은 기존 binary64 연산 결과로 부분 평가한다. 이를
변수에 대한 모든 반올림 경계의 증명으로 해석하지 않는다.

운영 탐색의 별도 결함도 수정했다. 이전 `search-fitness.ts`는 window가 들어간 비교를
NaN으로 취급해 실제로 쌓인 통계의 오차를 보지 못했다. 이제 `observedExpression`이
판정기가 이미 기록한 window 값을 읽는다. 큐를 다시 진행시키거나 캡처·회전 이력을
바꾸지 않으며, 아직 방문하지 않은 통계는 unknown으로 유지한다.
통계 없는 조건은 기존 컴파일 관측기를 그대로 사용해 매 조회의 재귀/기억 복사를 피한다.
브라우저 화면 점검에서 발견한 천체 없는 장면의 자동 검사 오류도 `auditStage`의 빈 천체
reduce를 수정해 없앴다. 존재하지 않는 천체를 향하는 전략을 대신 만들어 넣지 않는다.

`success-projection.ts`는 물리/기억 상태를 공유 SSA DAG에 대입한 성공 Boolean W(u)에서
제어 u의 영역을 역산한다. 입력별 필요 범위의 Cartesian 곱을 성공 집합으로 오인하지 않는다.
성공과 여집합을 모두 수축하고, 여집합이 비었으며 식이 영역 전체에서 정의될 때만 영역
전체를 성공으로 받는다. 또한 실패가 들어갈 수 있는 상자 바깥의 성공 slab들을 한 번에
추출하고 남은 core만 다시 처리한다. strict 경계에서 한 ulp 옆의 닫힌 끝점을 사용하되
그 사이의 실수 띠는 core에 남겨, 표현하지 못한 경계를 조용히 버리지 않는다.
이 방법은 [상보 수축을 이용하는 separator](https://ibex-team.github.io/ibex-lib/separator.html)의
원리를 프로젝트의 공유 DAG/조건부 구간 합집합에 적용한 것이다. IBEX 라이브러리를 사용하지 않는다.

각 영역에서 `regional-relation.ts`가 DAG를 다시 축약한다. 모든 입력에 대해 확정된 guard,
정확한 실수 항등식(0/1의 논리 곱 등), 관측되지 않는 종료 후 내부 기억을 줄인다. 특히
분리·연료·window 합성에서 1*1의 구간 오차가 참인 상태 비교를 계속 미결로 만들던 문제를
재현하고 고쳤다. 영역 가정 밖에서 이 컴파일 결과를 재사용하는 것도 거절한다.
최소 폭/작업 상한의 잔여 영역은 성공·실패 어느 쪽으로도 꾸며 반환하지 않는다.

`projectionGroups`는 인증된 닫힌 상자들의 합집합에 대해 기존 DD/시간 제약의 기호 접촉
관계로 연결 성분을 구한다. 실제 전수 상자 쌍 행렬을 만들지 않는다. 이 성분은 **현재 얻은
영역 합집합**에 대해서만 정확하며, 미결 경계나 다른 예약 순서까지 포함한 전체 비행 성분은
아니다. 제작소의 유사 경로 묶음은 기존 실제 비행 유사성 기준도 계속 적용한다.

중간 구간 쌍의 수가 32,768을 넘으면 실제 합집합이 작아도 중단되던 덧셈은 정렬 행 힙과
binary-search 건너뛰기로 바꿨다. 방문한 행 머리 수 K, 입력 조각 수 p,q, 결과 조각 수 R에
대해 병합 단계는 O(K(log p + log q)), 추가 공간은 O(min(p,q)+R)이다. 실제로 서로 떨어진
출력이 많은 경우의 조합 폭발을 없앴다고 주장하지 않는다. 로그 경계도 4,096개 캐시와
검증된 지수 후보 보정을 사용한다. 오차를 증명할 수 없으면 잘못 자르는 대신 범위를 넓힌다.

**2026-10-15 당시 연결한 컴파일러의 범위는 제한적이다.** 고정 순서·고정 시각·고정 방향의
진공 자유 공간에서 발사/출력 변수, 순간 추진 또는 연료 로켓, 다단 분리·부스터 독립 연소·
위성 분리, 해당 metric/event와 목표/window 이력을 합성한다. 유한 audit 시간 안의 성공만
다루며 무제한 임무의 완료 판정을 대신하지 않는다. 중력·대기·회전·접촉·이동 물체·추가
삼각/타원 계산 등 아직 연결하지 않은 모델은 원래 탐색으로 남고 임의로 단순화하지 않는다.
출력 이외의 연속 예약 시각/방향과 모든 구성까지 투영한 것은 아니다. 실제 게임의 이산
반올림까지 인증하지 않았으므로 인증 상자를 게임의 불가능 가지치기에 사용하지 않는다.

정확한 일치, 다변수 상관관계·strict 경계·분리 성분, 실제 브라우저 Worker→대표 예약→재생을
검사한다. 유한 대조점 검사는 전체 연속 정확성의 증명이 아니며 위 제한을 제거하지 않는다.
다음 연구 우선순위는 전체 tick의 접촉/착륙/회전/이동 천체 이력 연결, 가변 사건 시각에 따른
분할의 관계화, 모든 구성에 대한 상태 소거, 미결 경계를 포함하는 성공 집합 표현이다.

시간 네트워크의 방향 경로 일관성과 그래프 폭을 활용하는 연구를 참고해, 이 프로젝트에서는
조건부 가중 DD와 희소 소거를 결합했다. 아래 논문을 그대로 구현했다는 뜻은 아니다.

- [Planken 외, Computing All-Pairs Shortest Paths by Leveraging Low Treewidth](https://arxiv.org/abs/1401.4609)
- [Dechter·Meiri·Pearl, Temporal constraint networks](https://www.sciencedirect.com/science/article/pii/0004370291900066)
- [NASA, Edge-Valued Decision Diagrams](https://ntrs.nasa.gov/citations/20100024139)
- [Hybrid Hamilton–Jacobi reachability](https://arxiv.org/abs/2309.10893)
- [dReach의 유한 범위 δ-reachability](https://dreal.github.io/dReach/)
- [IBEX의 전방·역방향 수축과 구간 뉴턴 설명](https://ibex-team.github.io/ibex-lib/contractor.html)
- [Benhamou 외, Revising hull and box consistency](https://frederic.goualard.net/publications/revising-hull-and-box-consistency_benhamou_et-al_iclp1999.pdf)

시간 이론의 좋은 결과를 일반 비선형 전체 역산의 증명으로 전용하지 않는다.

## 2026-10-16 · C 선택 이후: 가변 사건 시각과 실제 비행 이력의 합성

사용자는 원래의 범용 전체 해 연구 목표를 유지하고 완성 시점을 확약하지 않는 C를
선택했다. 이 절은 구현한 연구 진전이며 최상단의 전체 성공 예약 기준을 완료 처리하지 않는다.

### 시간 전이와 좌표

`flight-clock.ts`는 실수 식인 예약 시각과 Boolean 존재 여부를 받아 하나의 공유 DAG를
만든다. 순서별 비행 목록, 시간 격자, 모든 사건 쌍의 순서 행렬을 만들지 않는다.
다음 실제 실행 규칙을 조건부 연산으로 유지한다.

- 외부 실행기의 0.1초 tick, 내부 최대 0.01초 적분, 예약 시각에서의 분할.
- 1e-8의 due 허용 오차 안에 들어온 사건은 engine 우선·원래 입력 순서로 처리한다.
  단순 시각 정렬로 바꾸면 근접 분리/점화의 의미가 달라진다.
- 같은 ID가 앞서 적용됐다면 같은 배치의 뒤 사건까지 억제한다. production 어댑터는
  모호한 중복 ID 템플릿을 명시적으로 거절하며 기존 탐색에 남긴다.
- 다음 사건은 present인 미실행 사건의 균형 min reduction으로 구한다. 빈 frontier는
  이미 계산한 remaining을 min의 중립값으로 사용한다. horizon-time을 다시 빼는 방식은
  마지막 dt가 실제 실행과 1ulp 달라지는 회귀가 있어 사용하지 않는다.
- 검사 창과 유한 임무 제한의 짧은 쪽에서 끝낸다. 무제한 임무 자체를 유한하다고 판정하지 않는다.

유한 H와 E개 사건에서 구성 상한 S는 `12·ceil(H/(0.1-1e-9)) + E + 1`이다.
각 tick의 보통 적분 조각을 보수적으로 잡고 사건 중단 조각을 E에 청구하는 상한이다.
매 스텝 O(E)의 DAG 연산, min의 추가 깊이 O(log E), 시간/공간 O(SE)이며
물리·목표/window 이력 비용은 별도다. 즉 E에 대해 최악 이차 항이 남으며 모든 물리의
선형/다항 종료 보장이 아니다. 실수 식과 일반 IEEE 실행의 모든 경계 동등성 증명도 아니다.
`pending` 잔여 guard를 보존하고, 별도 자원 한도에 걸린 구성을 전체 완료로 간주하지 않는다.
실제 게임의 빠른 정렬 커서 실행기는 이 기호 구성기로 대체하지 않는다.

`parameter-relation.ts`는 `parameterPlan`과 동일한 upper/lower 및 종속 [0,1] 좌표를
사용한다. 공통 `parameter-bounds.ts`로 상한 계산을 공유한다. 고정 시각 모순은 false
합법성 guard로 남기며 NaN 식을 만들거나 임의로 고치지 않는다. 실제 함수의 total-order,
독립 after-DAG, 종속 after-DAG를 363개 좌표 배정에서 대조한다.

### 구간 오차의 원인과 수정

처음 구현은 점별 성공 여부가 맞는데도 48개 영역에서 성공 상자를 하나도 추출하지
못했다. 같은 현재 시각이 반복 등장할 때 독립 구간처럼 취급되어 오차가 증폭됐다.
`additive-enclosure.ts`는 정의된 공유 DAG 항의 정확한 정수 계수를 유지한다.
`now + (event-now)` 및 그 차이에서 공통 항이 상쇄되므로 도달/due/min 분기를 증명할
수 있다. 불투명 비선형 항은 동일한 항끼리만 상쇄한다. 실제 연산 DAG를 재결합하지 않는다.
계수의 안전 정수 범위나 64개 항 한도를 넘으면 평범한 구간으로 되돌아가며 해를 버리지
않는다. N개 노드, 한도 L에서 추가 시간/공간 O(NL)이다. 미정의 분기는 상쇄하지 않는다.
정확한 hypot(0,0)이 root의 극소수 보수 확대 때문에 [0,Infinity]가 되던 문제도
정확한 0 항등식으로 제거했다.

시간 변수에는 `successProjection`의 내부 상자 우선 처리를 적용한다. 가장 넓은 축의
가운데 절반을 먼저 증명하고 양쪽 1/4 상자는 FIFO에 보존한다. 내부 상자도 성공식과
여집합의 수축으로만 채택한다. 중심 비행을 성공으로 가정하지 않으며 모든 잔여 영역을
보존한다. 유한 해상도/자원 제한의 미결 영역은 그대로 남는다. 이 순서 휴리스틱이 일반
미션의 시간복잡도를 바꾸거나 모든 성분을 빨리 찾는다는 주장은 하지 않는다.

실험한 guard 역상 경계 분할은 이 입력의 구간 hull 중첩을 충분히 해소하지 못했고
추가 수축 비용만 발생했다. 계측 후 제거했으며 미사용 최적화 모듈/설정으로 남기지 않는다.

### 제작소 연결과 실측

현재 production 어댑터는 진공 자유 공간에서 total-order 템플릿의 출력/연속 시각을
연료·분리·탑재체·GoalHistory/window 관계에 합성한다. after-DAG의 **실제 payload 재정렬**과
방향 변수는 seed에 고정되어 있다. FlightClock의 모든 시간 순서 표현 능력과 production의
모든 예약 순서 역산을 혼동하지 않는다. 중력/회전/접촉/이동 물체 등은 여전히 거절한다.
불법 입력·비유한 값·모호한 ID는 기존 탐색에 남기며 작업자 오류를 만들지 않는다.
원래 물리·목표를 완화하지 않으며 실제 엔진 재생을 통과한 대표만 기존 목록에 넣는다.

`tests/fixtures/timed-flight.ts`는 고정 조작 두 개의 시각만 자유롭게 둔 변위/시각/추진량
목표다. 스테이지의 referencePlans는 비어 있고 초기 좌표 [0,0]은 실패한다.
`node scripts/research-timing.mjs --compare` 2026-10-16 로컬 1회 관측:

비행 표본은 영역 추출에 사용하지 않았다. interval Newton 내부의 중심 구간 계산과
별개의 실제 대표 비행 검증은 수행한다. 네 상자의 연결 성분 네 개는 **채택된 상자
합집합**의 결과이지 실제 전체 해 그룹 네 개라는 뜻이 아니다. 실제 유사 비행 그룹화는
기존 경로 기준을 사용한다. 아직 해집합 전체도, 모든 임무 10초도 달성하지 못했다.

중력·목표 투영·전체 미션 해결 시간이 아니다.

연결, (3) 고정 조작 단어가 아니라 모든 허용 구성의 공유 소거, (4) 반올림/미결 경계까지
포함한 성공 집합과 전체 유사 성분 판정이다. 이번 부분 결과로 어느 조건도 완료 처리하지 않는다.
