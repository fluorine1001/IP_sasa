# 전역 풀이 탐색 알고리즘

2026-10-15. 임무 이름·의도한 해·성공 확률로 해를 구분하지 않습니다.
Condition/Expression과 본 게임의 0.01초 물리 스텝만 성공을 판정합니다.

## 연구 최종 목표와 현재 미달 항목

목표는 **전체 해 보장 또는 그에 준하는 해 집합 포괄성, 그리고 짧은 응답 시간**입니다.
빠른 첫 성공·큰 표본 수·낮은 실패율로 목표를 대체하지 않습니다. 현재 일반 동역학에서는
이 목표를 달성하지 못했습니다. 아래 경계값 연산도 그 공백을 모두 메우는 구현은 아닙니다.

### 추가 구현: 수식 DAG·역방향 구간 수축·전체 조작 도달 경계

`condition-domain.ts`의 하위 JSON 문자열 재직렬화를 제거했습니다. 예전에는 덧셈 깊이16의
키 하나가786,580글자이고 검사 중 생성한 키 총량은7,881,056글자였습니다. 지금은 입력 번호를
참조하는 구조 해시 DAG를 사용합니다. 같은 구조의 JSON 식/같은 행위자·대상은 공유하고,
시각 창·시간 기억·서로 다른 행위자는 섞지 않습니다. 입력이 좁혀지면 역방향 의존 간선으로
실제로 캐시된 상위 식만 무효화합니다. 이미 무효화한 조상으로 매번 다시 올라가지 않습니다.
표현 크기는 노드/간선 수에 비례하며 한 전방·역방향 수축 통과는 방문 DAG와 변경 간선에
비례합니다. 전체 비선형 임무의 다항 시간 완성을 뜻하지는 않습니다.

사칙연산·제곱·abs·min/max의 결과 구간을 입력 구간으로 역전파합니다. 예를 들어
x²≤1, y²≤1, xy≥2는 실수 표본 없이 모순을 확인합니다. 누적 연산의 원래 왼쪽부터의
반올림 순서를 유지하고 매 역연산에 바깥 방향 ulp를 포함합니다. 제곱근 역상은
`Math.sqrt` 후보를 방향 지정 곱셈 경계로 확인한 뒤 사용하며 확인 실패 시 넓게 남깁니다.
수축은32통과/32,768방문을 넘으면 보수적으로 멈춥니다. 중단을 불가능으로 간주하지 않습니다.

`control-envelope.ts`는 무중력·비접촉 모델에서 모든 예약 시각/방향/순서를 한 외곽 도달
집합으로 처리합니다. 순간 추진의 각 성분 변화는 전체 Δv 예산으로, 위치 변화는
초기 속도와 남은 시간의 구간 곱으로 감쌉니다. 예약 수 n의 조합/격자를 만들지 않습니다.
유한한 추진 횟수와 엔진 최소 전이 시간1e-9를 이용한 보수적 반올림 여유도 포함합니다.
실제 게임의 예산 비교 허용값1e-8을 누락하지 않습니다. 외곽 집합이 목표의 필요 구간과
충돌할 때만 `globalSearch`가 해당 모델 전체를 실제 비행0회로 제외합니다.

중력원/표면 접촉이 있거나 유한 로켓 연소의 이산 자원 누적을 검증하지 못한 경우에는 이
백엔드로 제거하지 않습니다. 유한 연소의 낙관적 Δv/자세 이동량 경계는 구현했지만 검증된
이산 전이로 승격하지 않았습니다. 무제한 시간에는 짧은 audit 창을 대입하지 않으며,
무제한 같은 시각 미세 추진의 누적 오차도 유한 횟수 증명과 혼동하지 않습니다.

`node scripts/benchmark-domain.mjs --baseline`은 이전 커밋을 읽기만 하여 비교합니다.
로컬 두 측정에서 깊이16 분석15.7–26.8ms→0.26–0.36ms, 새 고유 키332글자,
첨부2의 조건 분석3.8–5.8ms→0.41–0.66ms/고유 키895글자였습니다. 최대100만 추진 예약의
연속 시각 전체를 감싼 무중력 불가능 사례는0.74–0.87ms/실제 비행0회였습니다.
각각 해당 연산의 측정이지 일반 중력 임무 전체 해를 같은 시간에 찾는다는 결과가 아닙니다.
첨부2는128회 재현에서도 성공0이며 원본이나 판정을 완화하지 않았습니다.

이 단계는 구간 도달 가능성 연구의 외곽 포함 방향을 사용합니다. 참고:
[TIRA 원 논문](https://arxiv.org/abs/1902.05204),
[함수 변환 기반 구간 도달 가능성 연구](https://arxiv.org/abs/2401.11608).
검증 가능한 일반 중력/연소/접촉 집합 전이가 다음 핵심 공백인 점은 변하지 않았습니다.

### 이번 구현: 연속 제어 변수를 방정식으로 없애는 경계값 그래프

고정 단일 중력원, 대기 없는 순간 추진 모델에서 관리 궤도 표식의 참조/sequence를 읽습니다.
각 타원은 (a,e,p,ω,μ), p=a(1−e²), r(θ)=p/(1+e cos(θ−ω))로 표현합니다.
인접 타원의 접속은 다음 한 방정식으로 바뀝니다.

```
A cos θ + B sin θ + C = 0
A = p0 e1 cos ω1 − p1 e0 cos ω0
B = p0 e1 sin ω1 − p1 e0 sin ω0
C = p0 − p1
```

R=hypot(A,B)와 −C/R에서 비교차·접선·두 교차점·동일 곡선을 계산합니다.
이상적인 정확한 산술에서는 단일 타원 쌍의 교차점이 이 목록 외에 있을 수 없습니다.
실제 JS 구현은 반올림 허용 오차를 사용하므로 이를 검증된 실수 구간 증명으로 표기하지 않습니다.
200개 독립 방정식의 근 개수/원래 극좌표 식 잔차와 접선 회귀 검사를 추가했습니다.

각 교차점에서 두 회전 방향의 속도를 닫힌 식으로 계산해 Δv를 얻습니다.
이심근점이각→평균근점이각으로 비행 시간을 계산하고, hold/한 바퀴 최소 시간을 만족하도록
필요한 온전한 주기를 더합니다. 따라서 한 접속의 시각·출력·방향 3차원을 격자 분할하지 않습니다.
단일 원 궤도와 다른 출발 반경 사이에는 같은 물리식으로 접하는 전이 타원을 구성합니다.
관리되지 않는 조건·서로 다른 중심·일반 논리·다체 중력·유한 연소는 이 연산자로 해석하지 않습니다.

표식 k개에 대해 인접 교차 계산은 O(k), 저장은 O(k)입니다. 경로를 지연 생성하며 각 접속은
최대 두 교차점×두 회전 방향입니다. 경로 수 자체는 여전히 지수적으로 늘 수 있고,
모든 경로를 실제 엔진에 검증하는 비용은 사라지지 않습니다. 핵심 개선은 q분할의 3차원
격자 O(q³)를 한 접속당 상수 개의 방정식 근으로 바꾼 것이지, 검사 예산을 늘린 것이 아닙니다.

현재는 각 교차점의 **가장 이른 허용 도착**을 제안합니다. 추가 주기 대기 전부, 띠 내부의
목표 중심과 다른 궤도, 비접속 우회, 임의 추가 추진은 이 연산자가 포괄하지 않습니다.
일반 예약 문법은 그대로 조사합니다. 이 연산자의 종료를 전역 탐색 완료로 사용하지 않습니다.
예약 수·추진 예산·발사 한도를 통과한 후보만 같은 실제 엔진으로 검증하고 기존 그룹에 합칩니다.
첫 경계값 후보가 일반 후보에 밀려 늦게 전달되지 않도록 초기 그래프 확장16회 및 검증 실행
배분을 추가했습니다. 실제 시간 적분 간격·충돌·판정 조건은 바꾸지 않았습니다.

### 과정 전체가 중요한 임무의 재현

`tests/fixtures/hohmann-transfer.ts`는 초기 원 궤도0.5초→전이 타원5초→최종 원 궤도
실제 한 바퀴의 순서 임무입니다. 정답 기록은 비어 있습니다. 수학적으로 계산한 검증 계획은
실제 엔진에서 성공하고, 두 번째 추진 누락 및 최종 원 궤도에서 바로 출발은 실패합니다.
따라서 도착 상태만으로 전체 과정을 대신 판정하지 않습니다.

`node scripts/check-hohmann-search.mjs 32`의 2026-10-15 로컬 측정:

- 새 연산 이전: 1,024검사/121.063초, 성공0/그룹0.
- 새 연산 이후: 32검사/4.376초, 첫 성공0.394초/그때까지 시작한 검사4개, 그룹1.
- 별도 첫 성공 중단 측정: 0.380초. 대표는 별도 실제 엔진으로 성공 재확인.
- 32검사 실행의 가장 긴 generator.next는24ms. 이는 기기/GC 전체의 지연 보장이 아닙니다.

예산이 다르므로 전체 탐색의 배속 비율로 환산하지 않습니다. 32검사 종료는 예산 종료이며
전체 해 그룹 완료가 아닙니다. `--first`는 첫 성공 측정 전용이고 전체 완료와 구별해 출력합니다.

실제 운영 제작소의 미저장 초안도 내보낸 복사본으로 재현했습니다.
출발 전출력 가속0.15625/중력2.73205로, 전출력은40초 동안 발사대에서 뜨지 않습니다.
즉시1·2회 분리 후 점화한 경우도 목표 띠 전에 충돌합니다. 이 세 계획의 실패는 전체
예약 공간의 불가능 증명이 아닙니다. 장치/환경 문제와 탐색의 미발견을 혼동하지 않도록
같은 물리량·목표를 `stalled-surface-orbit` 회귀로 보존했습니다. 원본 초안은 변경하지 않았습니다.

### 전체 보장을 짧게 만드는 다음 연구의 구체적 계약

전체 제어를 한 격자에 얹지 않고, **제어 집합→목표 자동자→경계 접속 관계**를 공유하는
연산 DAG로 표현하는 방향을 채택합니다. 다음 항목은 설계이며 아직 구현 완료가 아닙니다.

1. Condition의 sequence/hold/once/capture를 목표 자동자로 컴파일합니다. 노드 키에는
   물리 모드·기체 집합·목표 기억·자원 상태를 포함합니다. 공간 위치만 같은 상태를 합치지 않습니다.
2. 자유 비행은 선형 전이 관계, 단일 중심 무추력은 Kepler 경계 관계로 대체합니다.
   주기 대기는 정수 회전 횟수 구간으로 저장하고 가능한 횟수를 일일이 비행하지 않습니다.
   고정 지점 사이 Lambert 다중 회전 가지도 빠짐없이 관계로 열거해야 합니다. 이번 구현은
   이 Lambert 연산이나 모든 회전 횟수 구간을 아직 제공하지 않습니다.
3. 유한 연소/다체 구간은 같은 0.01초 게임 전이의 의존성을 보존하는 Taylor/affine 집합과
   바깥 방향 오차 경계를 사용합니다. 연료 고갈·충돌·분리·점화·목표 경계에서는 가능한
   모드를 모두 분기합니다. 국소 최적화는 접속 제안용이며 집합 배제 근거로 쓰지 않습니다.
4. 전방 관계와 목표의 역방향 필요 관계를 교차하고, 정확히 같은 접미사 관계는 해시 DAG로
   공유합니다. 비선형 구간은 수축 후에만 분할합니다. 전체 변수마다 해상도를 곱하지 않고
   실제 의존하는 변수들의 separator에서 제거하는 것이 목표입니다. 일반 DAG의 폭 자체가
   클 수 있으므로 항상 다항 시간이라고 가정하지 않습니다.
5. 결과는 성공 표본 목록이 아니라 매개변수 집합의 합집합으로 저장해야 합니다. 모든 잎은
   전이·조건의 검증 가능한 포함/배제 근거를 가져야 합니다. 대표는 실제 엔진으로 재확인하고,
   셀의 직사각형 바깥 감싸기를 실제 성공 영역으로 사용하지 않습니다.

추가 구현/회귀 파일의 경계: `world/engine.ts` 전이의 집합 버전,
`world/conditions.ts` 자동자/집합 판정, `editor/` 관계 DAG와 연결성,
`tests/fixtures/` 경계-only·좁은 성공 띠·다체·분리체·첨부2 착륙입니다.
다음 통과 조건은 같은 입력/자유도에서 (a) 알려진 여러 떨어진 해 성분 전부,
(b) 경계 앞뒤의 건전한 포함/배제, (c) 10초 시점의 집합 미결량과 메모리,
(d) 첫 해와 마지막 새 그룹의 시간, (e) 대표 실제 재검증입니다.
10초가 지나도 완료 증거가 없으면 완전 탐색이라고 표시하지 않습니다.

### 짧은 시간 보장의 수학적 출력 조건

출력도 압축해야 한다는 근거는 현재 Expression 문법으로 직접 구성할 수 있습니다.
중력/추진 없는 자유 공간에서 발사 vx∈[−1,1]에 `sin(2π M vx)>1/2`를 요구하면,
정수 M에 대해 서로 떨어진 성공 띠가2M개 생깁니다. 각 띠는
`(j+1/12)/M < vx < (j+5/12)/M`, j=−M,…,M−1입니다.
발사 속도 원판과의 교차도 각 띠에서 비어 있지 않고 연결되어 있습니다.
정확한 연결 성분마다 대표를 모두 물질화하면 출력만 Ω(M)입니다.
이는 입력 상수의 비트 수에 비해 지수적일 수 있으며 P≠NP 가정도 필요하지 않습니다.

따라서 ‘어떤 입력에서도 모든 대표를10초 안에 전부 화면에 그린다’가 아닌,
주기적 띠·반복 관계 등은 압축된 집합 노드로 저장하고 대표를 요청 순번으로 만드는
출력 민감형 구조가 필요합니다. 현재 유사도 그룹은 가까운 띠를 묶을 수 있으므로 위 예를
현재 UI의 그룹 수 하한이라고 주장하지 않습니다. 일반 성공 집합의 표현 비용 하한입니다.
모든 물리/조건이 이 예처럼 압축 가능하다는 증명도 아닙니다.

이 접근의 근거와 한계는 [MIT 궤적 최적화](https://underactuated.mit.edu/trajopt.html)의
선형/희소 전사와 비선형 국소성, [dReal](https://dreal.github.io/)의 유계 δ-판정,
[ESA pykep](https://esa.github.io/pykep/)의 경계값 도구를 참고합니다.
δ-sat을 원래 게임 조건의 정확한 성공으로 바꾸거나, 이 도구들을 연결했다는 이유로
전체 모델10초 보장을 얻었다고 주장하지 않습니다.

## 경우 생성: 가중 문법 DP

한 계획은 초기 출력/방향, 조작 종류·대상의 인과 단어, 시각, 출력·방향 값입니다.
상태 s = (종류별 사용 횟수, 분리한 단 수, 위성 분리 비트 집합, 기체별 최소 점화 횟수/켜짐,
마지막 정규 기체 순위)이며 다음 합법 조작을 생성합니다.

F(s,0) = 1

F(s,n) = Σ[합법 간선 a] q(a,D) × F(next(s,a),n−1)

시간은 D+1개, 양수 출력은 D개, 방향은 D+1개입니다. 출력 0은 끄기 간선입니다.
초기 출력/방향의 경우 수는 별도로 곱합니다. 연료 로켓의 순간 Δv는 게임에서 금지되므로
생성하지 않습니다. 분리체의 점화/회전과 위성별 배치 순서를 포함합니다.
효과 없는 미존재 엔진 조작을 실제 기동으로 간주하지 않습니다.

BigInt 개수와 rank/unrank로 전체 배열 없이 순번을 계획으로 변환합니다.
서로소 순번 간격은 유한 순번 집합의 순열이므로 해당 격자의 경우를 누락하지 않습니다.
예약 길이를 교차 방문합니다. DP 10만 상태 또는 재귀 깊이 96을 넘으면 해당 길이는
명시적 스택 DFS로 지연 생성합니다. 집계 실패로 경로를 제거하지 않습니다.
252개/138개 경우 수와 실제 열거 수의 일치, 분리체·위성 순서, 금지된 Δv 제외를 검사합니다.

본체만 있는 구성은 시각을 이전 시각부터 남은 창의 비율로 표현합니다.
분리체를 포함하는 문법 구성은 아래 인과 DAG를 사용합니다. 수정 추진과 옛 전체 순서
템플릿은 기존 비감소 시각 변환을 유지합니다. 출력 불능 0 범위에 가짜 방향 차원을 추가하지 않습니다.

## 전수 비행 횟수가 아닌 문제 구조를 줄이는 변경

입력은 Stage의 실제 장치/자원/예약 한도, 초기 환경과 Condition/Expression입니다.
출력은 실제 엔진으로 성공한 대표 계획과 유사도 그룹입니다. 성공 조건을 생성 중에
느슨하게 하거나, 목표와 무관하다는 추측만으로 변수·기체를 지우지 않습니다.

### 독립 기체의 부분순서 몫

주 기체의 명령은 질량·분리 위치에 영향을 주므로 순서를 유지합니다. 같은 분리체의 명령도
순서를 유지합니다. 현재 엔진에서는 서로 다른 분리체의 제어가 다른 기체의 물리 상태를
변경하지 않습니다. 따라서 본체→1단 분리체→2단 분리체 순의 정규 단어 하나로 저장하고,
실제 시각에는 다음 간선만 둡니다.

- 같은 기체의 이전 명령 → 다음 명령.
- 그 기체를 만든 단 분리 → 그 분리체의 명령.

하나의 정규 단어에서 분리체 점화를 본체의 뒤쪽 예약보다 먼저 배치할 수 있습니다.
시각 t_i = L_i + u_i(U_i−L_i), L_i = max(직접 선행 시각, 제작자 하한), 0≤u_i≤1이며
고정된 자식의 상한은 역방향으로 부모에게 전파합니다. DAG의 모든 실행 가능 시각 할당에
대해 u_i를 역산할 수 있으므로 정규 단어화가 시간 끼워 넣기를 삭제하지 않습니다.
재구성 후 실제 명령을 시각 순으로 정렬하고 기존 엔진으로 실행합니다.
같은 시각의 사건은 기존 엔진이 모든 해당 명령을 적용한 뒤 물리/목표를 갱신하는 의미를 유지합니다.

이미 만들어진 두 기체의 길이 a,b 명령을 전역 단어로 섞으면 (a+b)!/(a!b!)개지만,
동일한 기체별 순서의 인과 구성은 하나입니다. 여러 기체에서는 이 중복이 다항계수로 커집니다.
이는 비행 표본을 덜 찍는 근사가 아니라 동일 실행 가능 예약들의 다른 저장 순서를 합치는 것입니다.
다만 각 시각/출력 할당의 물리 결과까지 같은 것으로 합치지는 않습니다.
앞으로 기체 간 충돌·도킹·반작용을 추가하면 이 독립성 전제를 재검사해야 합니다.

검사: 짧은 합법 전역 단어들을 독립적으로 전수 생성한 뒤 정규화한 집합과 DP 출력 집합을
비교합니다. 다른 기체의 시각 끼워 넣기, 분리 전 명령 거절, 고정된 자식에서의 상한 역전파,
실제 위치·속도·연료·목표 기억·적용 명령의 일치도 검사합니다 (`causal-search.test.ts`).

### 최소 점화 횟수와 DP 상태 동치

초기 점화 비용은 낙관적으로 0으로 둡니다. 끄기는 해당 기체를 꺼짐으로, 분리는 버린
엔진과 새 엔진을 꺼짐으로 취급하고 양수 출력이 꺼진 엔진을 켜면 최소 횟수를 더합니다.
실제 연료 고갈은 켜짐을 더 일찍 끝낼 수 있지만 최소 횟수를 낮추지는 못합니다.
최소 횟수부터 장치 한도를 넘는 양수 점화 단어만 제거합니다. 0 출력은 별도 끄기 단어로
대표됩니다. 낮은 점수·한 번의 실패·짧은 비행을 근거로 명령 단어를 제거하지 않습니다.

남은 길이와 점화/끄기/분리 한도에서 가능한 추가 점화의 상한 M을 구합니다.
최소 횟수+M≤장치 한도라면 그 기체의 켜짐/점화 이력은 어떤 미래 접미사도 막지 못합니다.
이 경우 DP 키에서 해당 이력을 *로 합칩니다. 그 외에는 이력을 유지합니다.
한도 1/2/3과 모든 짧은 점화·끄기 단어의 독립 열거가 같은 개수를 내는지 검사합니다.

원래 길이 N의 분기수 A 전수 생성은 O(A^N)개의 단어를 물질화합니다.
DP는 실제 도달한 몫 상태 S와 합법 간선 E만 계산합니다. 키 생성/BigInt 연산 비용을
별도로 두면 집계 시간 O(E), 공간 O(S), 순번 해독은 길이 N에 대해 O(N·A)입니다.
S 자체가 최악에는 지수적일 수 있습니다. 이를 일반 물리 문제의 다항 시간 해법이라고
주장하지 않습니다. 집계 상한 초과 시 명시적 스택 커서를 유지하며 경로를 누락하지 않습니다.

### 목표 구간의 논리 모순 제거

`condition-domain.ts`는 물리 비행 전에 동시 조건의 필요 구간을 전파합니다.
예: 같은 순간 높이≤a와 높이≥b(a<b), 장치의 최대값을 초과하는 상태,
실제 목표 시간 창보다 긴 연속 유지. IEEE-754 기본 산술은 바깥 방향으로 반올림합니다.
다른 시점의 sequence/capture/once, 독립 목표 완료 시각을 하나의 순간으로 합치지 않습니다.
기록·구간 통계·알 수 없는 운동은 제한 없는 구간으로 남깁니다. 제한 시간에서 관측 못한
것을 불가능으로 간주하지 않습니다. 반복/방문 상한도 '모름'이지 불가능이 아닙니다.
따라서 이 모듈은 조건의 모순 증명이지 중력 동역학의 도달 불가능 증명은 아닙니다.

### 정확한 공통 과거와 종료 접미사

`flight-prefix.ts`는 초기 상태와 이미 적용된 제어 값이 정확히 같은 실행의 과거를 공유합니다.
전 기체·천체·연료·목표 자동자/구간 기억을 복원하며, 달라진 미래 예약은 적분 분할 경계가
과거에 영향을 주지 않는 경우에만 허용합니다. 실제 성공/실패가 확정된 뒤의 모든 합법
접미사는 같은 종료 결과를 가지므로 그 부분을 다시 적분하지 않습니다.
가까운 위치끼리 합치는 상태 DP가 아니며 값 반올림도 없습니다. 최대 128개/직렬화 추산
4MiB 캐시를 넘으면 오래된 스냅샷만 제거합니다. 재사용이 없는 경우에도 결과는 변하지 않습니다.
목표 산술 AST는 연산 순서를 유지한 함수로 캐시하며 상태를 읽는 잎만 매번 평가합니다.
과거 기록/구간 표현식은 기존 해석기를 유지합니다. 이 역시 물리 간격을 키우는 근사가 아닙니다.

## 예약 길이·시간·정밀도의 교차 확장

fair-cases.ts의 층 k:

- 예약 길이: min(제작자 명시 탐색 상한, 실제 유한 예약 한도, 6+k).
- 정밀도: D = 초기 분할 수 × 2^k. 분할 수 자체도 BigInt입니다.
- 유한 임무: audit의 짧은 창이 아니라 실제 임무 종료 시각까지 검사합니다.
- 무제한 임무: 초기 검사 창 × (k+1). 이전 창의 관측 종료를 영구 실패로 캐시하지 않습니다.
- 무제한 타임라인: 해당 유한 실행 창 안에서 예약을 생성하며 다음 층에서 확장합니다.

일정 순번 i의 2진수 뒤쪽 0의 개수를 층으로 사용합니다.
0,1,0,2,0,1,0,3,… 순서이므로 층 k에는 1/2^(k+1)의 기회가 계속 옵니다.
거대한 낮은 정밀도 격자를 끝내야 다음 정밀도에 접근하는 구조가 아닙니다.
기본 6개는 빠른 탐색의 시작값이지 자동 전역 탐색의 영구 예약 한도가 아닙니다.
256개 자동 상한과 revision당 누적 8192회 상한은 제거했습니다.
제작자가 명시한 별도 예약 상한은 존중합니다.

층별 열거 커서는 유지하며 최근 4개 층의 DP 테이블만 뜨겁게 보관합니다.
오래된 DP 테이블은 비우되 순번과 DFS 커서를 버리지 않습니다.
무제한 진행 시 층 커서 메타데이터는 O(log(층 선택 횟수))만큼 증가합니다.
단순한 상수 계획·유한 시간의 실제 한 경우만 존재할 때는 열거가 종료됩니다.

## 실행 배분과 최적화

global-search.ts는 독립 경우 생성과 연속 값 개선을 결합합니다.
빠른 개선은 넓은 셀·저불일치 표본·여러 시작점의 좌표 탐색을 사용합니다.
목표 물리량의 오차는 다음 실험 순서만 정하고 성공 판정을 대신하지 않습니다.
관측용 오차 계산은 실제 목표 기억·구간 통계를 진행시키지 않습니다.
장치의 연료/추력/배기 속도로 계산한 여러 초기 제안과 다변수 differential evolution도
후보 순서에 사용합니다. 판정 시간 창/정확한 착륙 기록의 조건은 바꾸지 않으며, 접촉 전의
착륙 속도/기울기 오차는 현재 상대 속도/자세로 추정해 탐색 점수에만 사용합니다.
이 제안·오차·mutation 자체는 해 공간의 증명이 아닙니다.

비행 한 번은 0.1초 tick 최대 16개씩 진행한 뒤 양보합니다.
내부 0.01초 적분·사건 경계·판정 기억·명령 적용 ID를 그대로 보존합니다.
독립 경우 비행은 최대 8개를 교차 실행합니다. 한 긴 비행이 다음 경우 시작을 막지 않습니다.
빠른 구성들은 실제 검사 횟수를 라운드 단위로 배분합니다.
quantum마다 새 구성을 늘리거나 높은 점수의 한 구성에 예산을 몰아주지 않습니다.
이 문제는 512회 달 착륙 회귀 사례에서 재현한 뒤 수정했습니다.

- 값의 반올림 없는 캐시: 좌표 키와 실제 물리 계획 키를 사용합니다.
- 물리 계획 캐시 4096개: ID만 다른 같은 입력과 같은 실행 창의 재실험을 줄입니다.
- 같은 계획의 더 긴 실행 창은 독립 키입니다. 짧은 창의 실패를 재사용하지 않습니다.
- 성공·연결이 바뀔 때만 그룹/대표/범위를 다시 계산합니다.
- 각 계획의 매개변수는 WeakMap에 캐시합니다.
- 통합 그룹도 입력 그룹이 바뀔 때만 재생성합니다.
- 조사 비행은 전체 프레임을 저장하지 않습니다. 최대 128개의 실제 기체 중심 경로 점을 재사용하고, 최근 16개 표본의 경로만 캐시합니다. 선택한 대표의 영상만 다시 기록합니다.
- 변수별 Halton 소수는 서로 다르게 생성합니다. 17차원 이후 같은 소수를 반복하지 않습니다.
- 차단 후보도 같은 계획은 캐시하고 한 표본이라도 남으면 그 후보를 즉시 기각합니다.
- 물리 간격 증가·판정 완화·실패 점으로 미검사 구간 삭제는 최적화 수단이 아닙니다.

추가 예산은 실제 실행 중인 상태·열거 위치·셀·성공 그룹을 유지합니다.
환경/조건 변경은 기존 작업을 폐기합니다. 검증 기록 보관만으로 결과를 폐기하지 않습니다.

## 고차원 연속 제어: 국소 전이의 이산 수반

`trajectory-adjoint.ts`는 같은 실제 `tick`의 전방 기록과 역방향 벡터-야코비안 곱으로
모든 제어의 국소 개선 방향을 함께 계산합니다. 별도 추측 물리나 임무별 정답은 없습니다.
상태에는 위치·속도·자세·연료·분리체와 목표 기억을 포함하며, 제어와 무관한 천체 운동은
그대로 진행하되 미분 열에서는 제외합니다(시험 질점 계약). 전체 구간을 변수마다 두 번
재비행하는 대신 짧은 구간의 상태/제어만 차분합니다. 같은 최고 점수의 평탄 구간에서는
마지막 시점을 택해 뒤쪽 명령의 영향을 잘못 0으로 만들지 않습니다.

물리 전이 수를 S, 제어 수를 P, 구간 수를 K, 한 구간의 상태 폭을 d, 해당 구간에
실행되는 제어 수를 m이라 하면, 전체 비행 차분의 O(P·S)를 국소 계산의
O((d+m)·S)로 바꿉니다. P=K·m이고 d,m이 제한된 매끄러운 구간에서 의미 있는 차이입니다.
P개의 명령을 K번 다시 훑지 않도록 실행 ID→제어 목록으로 구간별 방문을 분리합니다.
과거 실행 ID는 영속 AVL/삽입 이력을 공유해 복사 O(1), 추가/조회 O(log P), 새 이력만
방문하며, 계획도 공유합니다. 따라서 과거 전체 복사로 숨은 O(P²) 항을 재도입하지 않습니다.
실제 비용에는 상태 복사·목표 기록의 크기와 AVL의 로그 비용이 별도로 포함됩니다.
긴 통계 기록이나 증가하는 기체/상태 폭에 상수 d를 가정하지 않습니다.

국소 차분은 수치적 **제안 방향**입니다. 검출된 분리·착륙·목표 이력 등의 모드 변경은
해당 미분을 버립니다. 다른 비매끄러운 경계에서 정확한 기울기를 보장하지 않습니다.
32–512변수·상태 폭128·기록 약8MiB 안에서만 이 보조 계산을 사용하고, 넘으면 기존의
공정 전역 조사를 계속합니다. 경사 방향의 3개 보폭을 실제 엔진으로 재검사하고 점수가
개선될 때만 사용합니다. 한 번의 조사에서 최대2회 적용하며, 실패한 국소 최적화로
예약/영역을 제거하지 않습니다. 추가 미분 비용은 후보 비행 횟수와 구분해 집계합니다.

이는 전체 비선형 성공 영역의 판정 알고리즘이 아니라, 고차원 제어 제안의 비용을
줄이는 변경입니다. 일반 임무의 지수적인 이산 경우 수까지 다항식으로 바꿨다는 주장은
하지 않습니다. 방법의 배경은 [MIT의 궤적 최적화](https://underactuated.mit.edu/trajopt.html)를
참고하되 이 구현은 게임의 실제 전이를 국소 유한 차분합니다.

## 실행 시간선: 정렬 인덱스와 커서

`world/event-schedule.ts`는 실행 중 불변인 예약을 정렬하고 다음 사건 커서를 저장합니다.
매 물리 스텝마다 모든 P개 명령을 두 번 훑던 예약 처리 항 O(S·P)를
O(S+P log P)로 바꿉니다. 같은 due 묶음은 엔진→수정 추진 및 원래 입력 순서를 유지하며,
기존 1e-8 시각 허용 오차·중복 ID·동시 명령의 의미를 보존합니다.
인접 사건 사이에서만 바꾸는 국소 시각 차분은 O(1) 갱신이고, 순서가 바뀌면 인덱스를
폐기합니다. 실제 게임/목표 적분 비용은 이 예약 처리 항과 별개입니다.

## 수학적 해석의 범위

이상적인 정확한 산술과 각 후보의 유한 실행을 가정하면 모든 유한 예약 단어와
유한 시간, 모든 dyadic 정밀도의 격자는 언젠가 방문합니다.
따라서 어떤 유한 단어/시간의 정규화 매개변수 공간에 **양의 폭을 가진 성공 영역**이
존재하면 충분한 층의 격자점이 그 영역에 들어갑니다. 실패 표본으로 가지치기하지 않으므로
오차 점수가 나쁜 영역도 영구 제거되지 않습니다.

이는 무제한 문제의 유한 시간 완료, 현재 예산이 전체의 거의 전부라는 비율,
정확히 한 점만 성공하는 조건, 실제 실수 동역학의 오차 없는 증명을 뜻하지 않습니다.
특히 JS Number 산술·충돌/조건의 사건 경계·0.01초 게임 모델과 연속 실제 물리는 다릅니다.
무제한 시간/길이에서 결과가 “없다”는 완전 판정도 제공하지 않습니다.
UI에 사실과 다른 전체 완전 탐색 완료나 성공 확률을 표시하지 않습니다.

더 강한 유한 구간 판정은 검증된 구간 적분, 모든 상태·시간·사건 표현식의 건전한
상·하한, 충돌/분리/재점화 경계의 분할, equality/경계-only 해 처리가 필요합니다.
이를 구현하지 않고 일반 표본의 최대/최소를 구간의 증명으로 취급하면 안 됩니다.
[dReach](https://dreal.github.io/dReach/)도 시간·모드 변화 상한과 δ를 명시하는 분석이며,
[δ-complete 연구](https://arxiv.org/abs/1204.3513)의 전제를 현재 시뮬레이터가 충족한다고 주장하지 않습니다.

## 그룹과 차단안

### 구간 통계의 영역 역산 연결

`inverse-projection.ts`가 지원하는 고정 순서·시각·방향의 진공 자유 공간 모델에서는
물리·자원·목표 기억을 같은 공유 수식으로 합성한 후 출력 제어의 연속 성공 영역을 구한다.
8종 window 통계가 포함되며, 입력별 필요 범위만 좁혀서 성공이라고 부르지 않는다.
성공과 그 여집합의 영역 수축으로 성공 상자를 인증하고, 실패 영역 바깥의 여러 구간을
한 번에 추출한다. 얻은 상자 합집합의 연결 성분마다 대표를 뽑아 원래 엔진으로 재검증하고
같은 풀이 목록에 넣는다. 별도의 ‘기준/임의 성공’ 분류는 없다.

이 연결은 중력·접촉·회전·가변 예약 시각을 포함한 전체 엔진 컴파일러가 아니다. 지원하지
않는 모델을 단순화하지 않고 기존 탐색으로 남긴다. 식의 영역 경계·최소 폭·자원 상한 때문에
미결 영역이 남을 수 있으며 전체 공간 완료로 표시하지 않는다. 게임의 binary64 경계를
증명하지 않았으므로 원래 게임 후보를 이 결과로 배제하지 않는다.
구간 점수 관측은 실제 판정기가 만든 window를 읽기만 하며 이력을 진행시키지 않는다.
상세 구조·검사·남은 연구는 [역산 연구 기록](research-symbolic-inverse.md)에 있다.

같은 실제 조작 원리/대상이고, 공간 이동량으로 재표본한 16점 경로와 모든 분리체
최종 상태가 공간 크기의 5% 안에서 유사하면 같은 풀이로 묶습니다.
절대 시각 차이는 분류 키가 아닙니다. 실제 성공 표본만 사용합니다.
¼·½·¾ 중간 비행의 성공 연결과 유사도 그룹은 구별합니다.
범위 직사각형의 모든 조합이 성공하거나 전체 연속 성분을 증명했다는 의미는 아닙니다.

차단안은 그림으로 관리하는 조건의 그림을 먼저 수정하고 같은 컴파일러로 조건을 만듭니다.
저장된 그룹 표본 모두를 실제 엔진으로 막은 경우만 제시합니다.
다른 해·제작 검증 기록을 특별히 보호하지 않으며 남는 실제 표본 수를 표시합니다.
최대 64개 유한 수정 후보·최대 16개 보관 표본의 결과이지 가능한 모든 수정의 증명은 아닙니다.
