# 전역 풀이 탐색 알고리즘

2026-10-14. 임무 이름·의도한 해·성공 확률로 해를 구분하지 않습니다.
Condition/Expression과 본 게임의 0.01초 물리 스텝만 성공을 판정합니다.

## 경우 생성: 가중 문법 DP

한 계획은 초기 출력/방향, 조작 종류·대상의 단어, 비감소 시각, 출력·방향 값입니다.
상태 s = (종류별 사용 횟수, 분리한 단 수, 위성 분리 비트 집합)이며 다음 합법 조작을 생성합니다.

F(s,0) = 1

F(s,n) = Σ[합법 간선 a] q(a,D) × F(next(s,a),n−1)

시간은 D+1개, 양수 출력은 D개, 방향은 D+1개입니다. 출력 0은 끄기 간선입니다.
초기 출력/방향의 경우 수는 별도로 곱합니다. 연료 로켓의 순간 Δv는 게임에서 금지되므로
생성하지 않습니다. 분리체의 점화/회전과 위성별 배치 순서를 포함합니다.
효과 없는 미존재 엔진 조작을 실제 기동으로 간주하지 않습니다.

BigInt 개수와 rank/unrank로 전체 배열 없이 순번을 계획으로 변환합니다.
서로소 순번 간격은 유한 순번 집합의 순열이므로 해당 격자의 경우를 누락하지 않습니다.
예약 길이를 교차 방문합니다. DP 10만 상태 또는 재귀 깊이 96을 넘으면 해당 길이는
명시적 스택 DFS로 지연 생성합니다. 집계 실패로 경로를 제거하지 않습니다.
252개/138개 경우 수와 실제 열거 수의 일치, 분리체·위성 순서, 금지된 Δv 제외를 검사합니다.

시각은 이전 시각부터 남은 창의 비율로 표현합니다. 이 변환은 비감소 시각 단체를
덮으며 같은 시각의 조작도 포함합니다. 엔진과 수정 추진의 매개변수 순서는 실제
조작 순서입니다. 출력 불능 0 범위에 가짜 방향 차원을 추가하지 않습니다.

## 예약 길이·시간·정밀도의 교차 확장

fair-cases.ts의 층 k:

- 예약 길이: min(제작자 명시 탐색 상한, 실제 유한 예약 한도, 6+k).
- 정밀도: D = 초기 분할 수 × 2^k. 분할 수 자체도 BigInt입니다.
- 유한 임무: audit의 짧은 창이 아니라 실제 임무 종료 시각까지 검사합니다.
- 무제한 임무: 초기 검사 창 × (k+1). 이전 창의 관측 종료를 영구 실패로 캐시하지 않습니다.
- 무제한 타임라인: 해당 유한 실행 창 안에서 예약을 생성하며 다음 층에서 확장합니다.

일정 순번 i의 2진수 뒤쪽 0의 개수를 층으로 사용합니다.
0,1,0,2,0,1,0,3,… 순서이므로 층 k에는 1/2^(k+1)의 기회가 계속 옵니다.
거대한 낮은 정밀도 격자를 끝내야 다음 정밀도에 접근하는 구조가 아닙니다.
기본 6개는 빠른 탐색의 시작값이지 자동 전역 탐색의 영구 예약 한도가 아닙니다.
256개 자동 상한과 revision당 누적 8192회 상한은 제거했습니다.
제작자가 명시한 별도 예약 상한은 존중합니다.

층별 열거 커서는 유지하며 최근 4개 층의 DP 테이블만 뜨겁게 보관합니다.
오래된 DP 테이블은 비우되 순번과 DFS 커서를 버리지 않습니다.
무제한 진행 시 층 커서 메타데이터는 O(log(층 선택 횟수))만큼 증가합니다.
단순한 상수 계획·유한 시간의 실제 한 경우만 존재할 때는 열거가 종료됩니다.

## 실행 배분과 최적화

global-search.ts는 독립 경우 생성과 연속 값 개선을 결합합니다.
빠른 개선은 넓은 셀·저불일치 표본·여러 시작점의 좌표 탐색을 사용합니다.
목표 물리량의 오차는 다음 실험 순서만 정하고 성공 판정을 대신하지 않습니다.
관측용 오차 계산은 실제 목표 기억·구간 통계를 진행시키지 않습니다.

비행 한 번은 0.1초 tick 최대 16개씩 진행한 뒤 양보합니다.
내부 0.01초 적분·사건 경계·판정 기억·명령 적용 ID를 그대로 보존합니다.
독립 경우 비행은 최대 8개를 교차 실행합니다. 한 긴 비행이 다음 경우 시작을 막지 않습니다.
빠른 구성들은 실제 검사 횟수를 라운드 단위로 배분합니다.
quantum마다 새 구성을 늘리거나 높은 점수의 한 구성에 예산을 몰아주지 않습니다.
이 문제는 512회 달 착륙 회귀 사례에서 재현한 뒤 수정했습니다.

- 값의 반올림 없는 캐시: 좌표 키와 실제 물리 계획 키를 사용합니다.
- 물리 계획 캐시 4096개: ID만 다른 같은 입력과 같은 실행 창의 재실험을 줄입니다.
- 같은 계획의 더 긴 실행 창은 독립 키입니다. 짧은 창의 실패를 재사용하지 않습니다.
- 성공·연결이 바뀔 때만 그룹/대표/범위를 다시 계산합니다.
- 각 계획의 매개변수는 WeakMap에 캐시합니다.
- 통합 그룹도 입력 그룹이 바뀔 때만 재생성합니다.
- 조사 비행은 전체 프레임을 저장하지 않습니다. 최대 128개의 실제 기체 중심 경로 점을 재사용하고, 최근 16개 표본의 경로만 캐시합니다. 선택한 대표의 영상만 다시 기록합니다.
- 변수별 Halton 소수는 서로 다르게 생성합니다. 17차원 이후 같은 소수를 반복하지 않습니다.
- 차단 후보도 같은 계획은 캐시하고 한 표본이라도 남으면 그 후보를 즉시 기각합니다.
- 물리 간격 증가·판정 완화·실패 점으로 미검사 구간 삭제는 최적화 수단이 아닙니다.

추가 예산은 실제 실행 중인 상태·열거 위치·셀·성공 그룹을 유지합니다.
환경/조건 변경은 기존 작업을 폐기합니다. 검증 기록 보관만으로 결과를 폐기하지 않습니다.

## 수학적으로 의미하는 것과 의미하지 않는 것

이상적인 정확한 산술과 각 후보의 유한 실행을 가정하면 모든 유한 예약 단어와
유한 시간, 모든 dyadic 정밀도의 격자는 언젠가 방문합니다.
따라서 어떤 유한 단어/시간의 정규화 매개변수 공간에 **양의 폭을 가진 성공 영역**이
존재하면 충분한 층의 격자점이 그 영역에 들어갑니다. 실패 표본으로 가지치기하지 않으므로
오차 점수가 나쁜 영역도 영구 제거되지 않습니다.

이는 무제한 문제의 유한 시간 완료, 현재 예산이 전체의 거의 전부라는 비율,
정확히 한 점만 성공하는 조건, 실제 실수 동역학의 오차 없는 증명을 뜻하지 않습니다.
특히 JS Number 산술·충돌/조건의 사건 경계·0.01초 게임 모델과 연속 실제 물리는 다릅니다.
무제한 시간/길이에서 결과가 “없다”는 완전 판정도 제공하지 않습니다.
UI에 사실과 다른 전체 완전 탐색 완료나 성공 확률을 표시하지 않습니다.

더 강한 유한 구간 판정은 검증된 구간 적분, 모든 상태·시간·사건 표현식의 건전한
상·하한, 충돌/분리/재점화 경계의 분할, equality/경계-only 해 처리가 필요합니다.
이를 구현하지 않고 일반 표본의 최대/최소를 구간의 증명으로 취급하면 안 됩니다.
[dReach](https://dreal.github.io/dReach/)도 시간·모드 변화 상한과 δ를 명시하는 분석이며,
[δ-complete 연구](https://arxiv.org/abs/1204.3513)의 전제를 현재 시뮬레이터가 충족한다고 주장하지 않습니다.

## 그룹과 차단안

같은 실제 조작 원리/대상이고, 공간 이동량으로 재표본한 16점 경로와 모든 분리체
최종 상태가 공간 크기의 5% 안에서 유사하면 같은 풀이로 묶습니다.
절대 시각 차이는 분류 키가 아닙니다. 실제 성공 표본만 사용합니다.
¼·½·¾ 중간 비행의 성공 연결과 유사도 그룹은 구별합니다.
범위 직사각형의 모든 조합이 성공하거나 전체 연속 성분을 증명했다는 의미는 아닙니다.

차단안은 그림으로 관리하는 조건의 그림을 먼저 수정하고 같은 컴파일러로 조건을 만듭니다.
저장된 그룹 표본 모두를 실제 엔진으로 막은 경우만 제시합니다.
다른 해·제작 검증 기록을 특별히 보호하지 않으며 남는 실제 표본 수를 표시합니다.
최대 64개 유한 수정 후보·최대 16개 보관 표본의 결과이지 가능한 모든 수정의 증명은 아닙니다.
