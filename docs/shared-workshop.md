# 독립 제작소와 공유 스테이지 서버

## 로컬 제작

`editor.cmd`를 열면 독립 경로 **/editor.html**에서 제작합니다. JSON 가져오기/내보내기, 초안 저장, 검사 후 공개를 사용할 수 있습니다. `play.cmd`는 서버 없이 실행할 게임을 빌드합니다. 예전 /?editor=1은 개발 호환 경로이며, 공유 서버에서는 /editor.html을 사용합니다.

## 팀 공유 서버

서버 담당자의 clone에서 Node.js 24 이상으로 다음을 실행합니다.

```powershell
npm ci
npm run workshop
```

이 명령은 게임과 제작소를 dist-workshop에 빌드하고 http://127.0.0.1:5180/ 와 http://127.0.0.1:5180/editor.html을 제공합니다. 게임은 공개 목록만 읽고 제작소는 별도 저장 API를 사용합니다. 서버를 끄면 공유 서비스도 종료됩니다. 게임의 일반 오프라인 실행과는 별개입니다.

LAN 공유는 서버 관리자가 24자 이상의 비공개 편집 키를 환경변수 STAGE_EDITOR_TOKEN으로 설정한 뒤 `npm run workshop:lan`을 실행합니다. 키를 소스·JSON·스크린샷·Git에 넣지 마세요. 원격 제작자는 서버의 /editor.html에서 편집 키를 입력합니다. 키는 탭 메모리에만 두고 저장하지 않습니다. 인터넷 공개는 HTTPS 역방향 프록시, 방화벽, 접근 관리가 별도로 필요합니다. 현재 무료 운영 주소는 게임 `https://ip-sasa-workshop.onrender.com/`, 제작소 `https://ip-sasa-workshop.onrender.com/editor.html`입니다. 서비스는 `codex/free-workshop-deployment` 브랜치의 Render Free + Neon Free로 운영합니다.

다른 clone의 게임도 같은 목록을 사용하려면 `src/stages/server-config.json`의 url에 관리자가 제공한 서버 주소를 넣고 빌드해 공유합니다. 제작소 보관함에서 연결한 주소는 해당 브라우저의 로컬 설정에도 저장됩니다. 공개 GET /api/stages는 다른 로컬·파일판의 읽기를 허용합니다. 지정한 서버에 연결할 수 없으면 빌드에 포함된 스테이지로 돌아갑니다. 임무·튜토리얼 목록을 다시 열 때 최신 공개 목록을 가져와 추가·수정·삭제를 반영합니다. 이미 진행 중인 임무의 환경은 바꾸지 않습니다.

## 저장·공개·충돌·복구

실행/접속 절차는 [RUNNING](../RUNNING.md), 전체 저장/빌드 구조는 [README](../README.md)에 있습니다. 브라우저 보관함·서버 초안·마지막 공개본·Git 빌드 데이터를 구분합니다.

보관함은 서버의 공개·초안을 함께 나열합니다. 최신본을 열어 수정한 후 초안 저장 또는 검사 후 게임에 추가를 누릅니다. 초안은 게임 목록에 나타나지 않습니다. 서버에서도 구조·실제 성공 검증 기록·단순/임의 성공 검사를 다시 수행한 뒤 공개합니다. 제작 검증 기록과 예전 변형 데이터는 공개 API에서 제거합니다.

초안 저장은 이미 공개한 내용을 덮거나 철회하지 않습니다. 목록은 편집 이름과 게임 공개 이름/미공개 수정 상태를 구분합니다. 공개 해제는 편집본을 남기고 게임 목록에서만 내립니다. 파일 저장소는 data/stages/<UUID>.json에 편집본, data/releases/<UUID>.json에 마지막 공개 스냅샷을 저장합니다. releases의 JSON null은 명시적 철회입니다. **두 경로를 함께 Git으로 공유해야 새 clone의 오프라인 빌드도 같은 공개본을 사용합니다.** 예전 .stage-workshop/releases는 읽기 호환만 남깁니다. PostgreSQL은 별도 published_raw/published_revision 열을 사용합니다.

수정·삭제 요청은 읽었을 때 받은 SHA-256 revision을 If-Match에 넣습니다. 다른 사람이 먼저 수정하면 409로 거절하고 최신본을 다시 열어 비교하게 합니다. 오래된 clone이 최신 스테이지를 조용히 덮어쓰지 않습니다. 쓰기는 직렬화하고 임시 파일을 rename해 완성본만 노출합니다.

무료 인터넷 서버는 [Render + Neon 설정](free-hosting.md)을 사용합니다. DATABASE_URL이 있으면 같은 API가 PostgreSQL 저장으로 전환하며 각 수정은 행 잠금·revision 확인·이전본 저장을 하나의 트랜잭션에서 수행합니다. 동시에 새 UUID를 저장해도 먼저 저장한 내용을 덮어쓰지 않습니다. 클라우드에서는 DB 연결 주소가 없으면 기동을 거절하고 재시작으로 사라지는 임시 파일 저장으로 대체하지 않습니다.

삭제는 두 번 확인하며 서버의 `.stage-workshop/trash`로 옮깁니다. 수정 전 버전도 `.stage-workshop/history/<UUID>`에 남깁니다. 복구하려면 관리자가 해당 JSON을 가져와 현재 서버 상태를 확인한 뒤 다시 저장합니다. 이 폴더는 Git에서 제외하므로 서버 관리자는 별도 백업을 해야 합니다. 실제 협업 코드·자산·계약 변경은 여전히 개인 브랜치와 PR로 공유합니다. 실행 중 서버 데이터가 다른 clone의 Git 파일까지 자동 변경되는 것은 아닙니다.

DB 저장에서는 workshop_stages의 deleted 표시로 복구 가능한 삭제를 하고 workshop_history에 이전 JSON을 남깁니다. workshop_meta의 최초 시드 표시를 함께 백업·이전해야 재부팅 후 초기 스테이지를 다시 넣지 않습니다. 복구는 이전 JSON을 에디터로 가져와 같은 UUID로 다시 저장하며, 별도 영구 삭제 API는 제공하지 않습니다.

권한 없는 공개 요청은 읽기 전용입니다. 편집 키를 설정한 서버는 로컬 요청도 키를 요구합니다. 다른 출처의 private API 접근은 STAGE_ALLOWED_ORIGINS에 관리자가 명시한 출처만 허용합니다. 편집 키가 없는 개발 서버는 loopback에서만 제작 API를 사용합니다.

## 공개 검사의 격리와 동시 작업

공개 판정은 Node 작업자에서 실제 엔진으로 실행하며 HTTP 이벤트 루프를 막지 않습니다. 한 서버에서 하나씩 처리하고 최대 대기 8개·검사당 120초·작업자 heap 256MiB로 제한합니다. 한도 초과는 공개 실패로 반환하며 검사를 생략해 공개하지 않습니다. 검사 중에도 목록 읽기는 계속됩니다. 적용 시점의 revision을 다시 비교하므로 검사 도중 다른 제작자가 저장한 최신본을 덮어쓰지 않습니다.

편집 인증은 주소별 1분 동안 실패 12회를 허용하고 이후 429·Retry-After를 반환합니다. 공개 목록 읽기는 이 제한으로 막지 않습니다. 키는 운영자가 직접 설정하며 로그·공개 JSON에 넣지 않습니다. 이 방어는 운영 호스트의 TLS·방화벽·백업을 대신하지 않습니다.
