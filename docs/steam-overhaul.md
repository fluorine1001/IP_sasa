# 스팀 출시 수준 개편 · 진단과 계획 (2026-11)

이 문서는 `claude/steam-overhaul` 브랜치 개편의 기준입니다. 데스크톱 1440×900과 휴대폰 390×844에서 15개 화면을 실제로 캡처해 보고, 코드와 CSS를 세어 본 결과에 근거합니다.

## 1. 판단 기준

플레이어가 "읽고 → 이해하고 → 결정하는" 과정을 방해하는지를 기준으로 삼습니다. 기능이 있느냐보다 사람 눈에 어떻게 보이느냐를 먼저 봅니다.

## 2. 측정한 사실

- CSS 안의 서로 다른 색 값 **560개**, 글자 크기 **35종**(10·11·12px가 165곳), `border-radius` 20종, `box-shadow` 29종, `!important` 17개.
- 게임 화면 하나에 CSS 층 7개가 순서대로 덮어씁니다. 같은 버튼이 4개 파일에서 다시 칠해집니다. 불통일의 근본 원인입니다.
- 글꼴은 시스템 글꼴(맑은 고딕/애플 고딕)뿐이어서 컴퓨터마다 다르게 보이고, 타이틀 로고가 일반 본문 글꼴입니다.
- 효과음은 삼각파 '삑' 하나를 음높이만 바꿔 네 곳에서 씁니다. 엔진, 분리, 착지, 충돌, 버튼 소리가 없습니다.

## 4. 게임 설계 문제와 해결 방향

### 4.1 시행착오가 다음 판단으로 이어지지 않는다

지금은 비행이 끝나면 경로와 결과만 남습니다. "그 순간 엔진을 껐다면 어떤 궤도였는가"를 읽을 도구가 없어서, 다음 계획의 어느 값을 얼마나 바꿀지 감으로 정합니다.

**해결: 궤도 계산기 (제한적 예측).** 사용자 결정에 따라 다음만 계산해 보여 줍니다.

1. 현재(또는 다시보기에서 고른 순간)의 상태로 가장 강하게 끌어당기는 천체에 대한 케플러 원뿔곡선(원·타원·쌍곡선)을 그립니다.
2. 근점·원점의 고도, 주기, 이심률, 원궤도까지 필요한 속력 차를 숫자로 보여 줍니다.
3. 계획 화면에서는 직전 비행 기록의 같은 시각 상태에 예약한 순간 추진을 더한 원뿔곡선을 "직전 비행 기준 계산"으로 보여 줍니다. 그 시각 이전의 계획이 바뀌었으면 "기준 비행과 달라짐"이라고 표시하고 그리지 않습니다.

다체 중력, 대기, 엔진 연소 중 궤도, 착륙·충돌은 계산하지 않습니다. 이것들은 여전히 실제 비행으로 확인합니다. 지금은 "추진 하나를 바꾸면 결과가 뒤죽박죽"이던 냉가스 임무(6, 7, 8, 11, 14)에서 추진 방향·세기와 궤도 모양의 관계를 직접 읽을 수 있게 됩니다.

### 4.2 착륙과 냉가스 임무가 운에 기댄다

- **착륙 계산기:** 다시보기의 각 순간에 "지금 최대 출력으로 감속하면 멈추는 데 필요한 높이"와 실제 높이를 나란히 보여 줍니다(현재 질량·추력·표면 중력으로 계산하는 정지 거리). 결과 카드에는 "접지 2.1초 전에 점화했다면" 같은 정답 대신, 접지 순간의 수직·수평 속도와 한계, 그리고 마지막 1초의 높이-속도 곡선을 보여 줍니다.
- **최근접 기록:** 목표 천체·위성과 가장 가까웠던 시각과 거리를 기록하고 지도에 표시합니다. 다음 계획에서 "더 일찍/늦게"를 판단할 근거가 됩니다.
- **시도 비교:** 두 시도의 경로를 색으로 겹치고, 계획 차이(어떤 값이 얼마나 달라졌는지)와 결과 차이(최고 고도, 최근접 거리, 접지 속력)를 한 표로 보여 줍니다.

**비행 기록 그래프 (구현, 2026-11-05).** 타임라인 바로 아래에 지난 비행에서 판정이 실제로 잰 값(목표의 비교 대상: 높이, 중심까지 거리, 상대속력 …)을 같은 시간축으로 그립니다. 최신 시도는 실선, 직전 시도는 점선, 목표 기준값은 노란 점선과 띠입니다. 측정값이 하나도 변하지 않는 임무(착륙 정착 여부 같은 참/거짓 목표)는 기록 프레임에서 읽은 "표면에서 높이"와 "상대 속력"을 대신 보여 줍니다. 계획 단계에서 타임라인의 시각을 고르면 그래프의 값, 그리고 지도 위 지난 비행의 그 시각 위치(움직이는 천체의 그 시각 위치 포함)가 함께 움직입니다. "지난번 7.8초에 달까지 1.85 u였다"를 읽고 그 시각에 예약을 놓는 흐름입니다. 기록일 뿐 예측이 아니므로 계약 안에 있습니다.

- 판정 측 변경은 수동 기록뿐입니다: `Run.recordSeries`가 켜진 비행(플레이 화면)만 비교 원자마다 0.05초 간격 값을 `GoalProgress.series`에 남기고, 판정·`closest`는 바뀌지 않습니다(`tests/flight-log.test.ts`가 검사). 검색·감사 실행은 기록하지 않습니다.

### 4.3 목표를 어떻게 만족하는지 모른다

- 임무에 들어가면 **임무 브리핑**이 먼저 뜹니다: 목표 한 줄, 성공 기준을 사람 말로 푼 항목(숫자와 단위 포함), 주어진 기체·천체 정보, 이번 임무에서 처음 쓰는 조작.
- 목표 패널은 조건마다 **실시간 진행**을 보여 줍니다: 현재 값, 필요 범위, 충족 여부, 유지 시간 막대.
- 결과는 "어떤 조건이 얼마나 모자랐는지"를 조건별로 보여 줍니다.
- 메달 기준을 임무 카드와 브리핑에 적습니다.

### 4.4 진행과 구성이 초안처럼 보인다

- 첫 실행 흐름: 타이틀 → (처음이면) 첫 비행 훈련으로 바로 연결 → 임무 목록.
- 타이틀에 "이어하기", 제작진, 종료(데스크톱), 버전.
- 챕터 진행: 챕터 완료율, 메달 수, 다음 추천 임무 강조. 강제 잠금은 하지 않습니다(기존 결정 유지).
- 일시정지 메뉴(Esc): 계속, 다시 발사, 설정, 임무 나가기. 조작키 도움말(?).
- 결과 화면: 시도 횟수, 비행 시간, 남은 연료/추진, 메달 획득 연출.

## 5. 디자인 시스템

- **토큰 한 곳(`src/ui/tokens.css`)**: 색은 역할 이름으로만 씁니다(`--c-bg`, `--c-surface-1..3`, `--c-text`, `--c-text-dim`, `--c-accent`, `--c-ok`, `--c-warn`, `--c-danger`, `--c-info`, 단계 색은 `--c-stage-1..4`처럼 기체 전용). 글자 6단계(13/15/17/21/28/44px), 간격 4px 격자, 모서리 3종, 그림자 3종, 움직임 2종.
- **글꼴**: Pretendard(본문, OFL)를 앱에 포함합니다. 숫자는 고정폭 숫자(tabular-nums)를 씁니다.
- **재질 하나**: 관제 콘솔 금속 패널을 기본 표면으로 통일하고, 종이 재질은 "문서"(브리핑·결과 보고서)에만 씁니다.
- **색의 뜻 고정**: 노랑 = 지금 할 주 행동, 초록 = 충족·성공, 빨강 = 실패·위험, 하늘 = 정보·계산 도구. 기체 단 색은 단 표시에만 씁니다.
- **공용 구성 요소**: 버튼(주/보조/고스트/위험 × 대/중/소), 아이콘 버튼(항상 접근 가능한 이름과 툴팁), 패널, 수치 칸(라벨·값·단위·비교 기준), 진행 막대, 토글, 슬라이더(값 표시), 대화상자, 알림, 키 표시(`kbd`).
- **용어집**: 임무, 발사, 출력, 추진(냉가스), 분리, 기록, 다시보기 등 한 개념에 한 단어. `src/i18n/ko.ts`에 문자열 키로 모읍니다.

## 6. 소리

Web Audio로 실시간 합성합니다(파일 없음). 음향 버스: 전체 / 효과 / 인터페이스 / 배경. 압축기로 소리 크기를 다듬습니다.

| 분류       | 소리                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------- |
| 엔진       | 점화(폭발성 시작음), 연소 굉음(필터 잡음 + 저음, 출력·대기 밀도에 따라 음색 변화), 소진·끄기 |
| 기체       | 단 분리(금속 충격 + 화약), 위성 분리, 회전 자세 제어 분사, 냉가스 추진(짧은 '푸슉')          |
| 사건       | 접지(쿵), 추락(폭발 + 잔향), 목표 조건 하나 충족(맑은 음), 성공 팡파르, 실패 하강음          |
| 인터페이스 | 클릭, 마우스 올림, 토글, 확인, 뒤로, 예약 놓기/옮기기/지우기, 발사 카운트다운                |
| 배경       | 우주 공간의 낮은 지속음(설정에서 끄기 가능), 대기권 안에서는 바람 소리                       |

## 7. 구현 순서

1. 토대: 토큰·글꼴·공용 구성 요소, i18n 구조, 소리 엔진.
2. 계획/비행 화면 재구성: 브리핑, 목표 실시간 진행, 천체·기체 정보 카드, 궤도 계산기, 착륙 계산기, 시도 비교, 결과 보고서.
3. 메타: 타이틀, 임무 목록, 첫 실행, 일시정지, 설정, 튜토리얼 허브, 안내서.
4. 검증: format, tsc, 단위, 브라우저 회귀, 두 화면 크기 스크린숏 재검토.
