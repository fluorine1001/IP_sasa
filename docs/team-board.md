# 세 역할의 작업 보드

담당 이름·현재 UUID·기능은 GitHub Issue에서 정합니다. 이 파일은 동시 편집하는 진행표가 아니라 역할 경계와 인수 기준입니다.

| 역할                  | 독립 단위                                        | 완료 기준                                                                                       |
| --------------------- | ------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| 설정 / 가이드 창 제작 | settings/·tutorial/ 코드와 CSS, 메인 도움말 내용 | 저장/기본값/실제 적용, 단일 훈련의 행동 확인·수동 진행, 정답 미노출, dispose 정리               |
| UI 제작               | 공통 관제석·렌더러·제작소의 화면/스타일          | 모든 구/신 스테이지의 공통 적용, 좁은/큰 화면, 휠/드래그/키보드, 실행·재생 잠금, 판정/물리 불변 |
| 스테이지 제작         | 자신의 UUID 편집본·공개본·전용 자산              | 실제 성공과 실패 단서, 주변 조작 여유, 공개 검사, 저장/공개 구분, 다른 clone의 같은 빌드        |

새 Settings 키·실습 관찰 이벤트·공용 입력/화면 계약이 필요하면 작은 선행 변경으로 조율합니다. [Git 절차](../CONTRIBUTING.md), [전체 구조](../README.md), [실행·접속](../RUNNING.md)을 따릅니다. title.ts의 도움말과 메뉴 배치는 두 역할이 겹치므로 작업 순서를 먼저 정합니다.

## 공통 코어는 별도 계약 책임

world/physics·Condition·검색·저장/API·빌드의 결함을 위 세 역할의 콘텐츠 작업으로 떠넘기지 않습니다. 기존 ‘게임 시스템’이라는 네 번째 협업자 역할을 새로 전제하지 않습니다. 코어 변경은 회귀 검사와 계약 문서까지 함께 인계합니다.

현재 남은 가장 큰 코어 과제는 일반 비선형 전체 성공 예약 역산과 사용자 두 번째 착륙 원본입니다. 주 기체 상실 뒤 독립 기체의 계속 운용, 전체 연속 그룹 차단 증명도 미완료입니다. 상세 재현/통과 기준은 [remaining-work](remaining-work.md)에 있으며, UI 완성이나 첫 성공 발견으로 대신 완료 처리하지 않습니다.

## 파일별 실무 경계

- flight/screen.ts는 세션, timeline.ts는 시간 바, planner.ts는 예약 편집, propulsion.ts/engine-bench.ts는 기체 시각 안내입니다.
- world/replay.ts는 녹화 상태, render/rocket-sprite.ts는 실제 동체 아트입니다. hull.ts 치수는 물리와 그림이 공유합니다. craft-locator.ts의 먼 거리 식별 표시는 충돌 크기가 아닙니다.
- 스테이지 공개 스냅샷은 data/releases/<UUID>.json입니다. 편집본과 함께 Git으로 공유하고, 브라우저 보관함·원격 DB와 혼동하지 않습니다.
- 설정/훈련 화면은 다른 화면이나 물리를 직접 import하지 않습니다. 공용 core 계약으로 필요한 이벤트를 받습니다.
